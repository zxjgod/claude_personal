Claude Code Replica 启动教程
============================

项目路径：
C:\Users\20616\Desktop\claude_compare\claude_personal

本教程说明如何在本机启动这个 AI coding assistant 项目，并用你当前 .env 里的 DeepSeek API 进行真机使用。


一、前置要求
----------------

1. 安装 Node.js
   建议 Node.js 20 或更高版本。

   检查命令：
   node -v
   npm -v

2. 进入项目目录
   在 Git Bash / PowerShell / CMD 中执行：

   cd C:\Users\20616\Desktop\claude_compare\claude_personal

3. 安装依赖
   如果 node_modules 已存在可跳过；否则执行：

   npm install


二、配置 .env
----------------

项目根目录需要有 .env 文件。
你当前项目已经有 .env，且配置的是 DeepSeek API。

.env 至少需要包含这些键：

LLM_PROVIDER=deepseek
LLM_API_KEY=你的 API key
LLM_MODEL=deepseek-v4-pro
LLM_MAX_TOKENS=4096
LLM_TEMPERATURE=0.1
PERMISSION_MODE=default

说明：
- LLM_PROVIDER：模型供应商。你当前用 deepseek。
- LLM_API_KEY：API key。不要提交到 git，不要发给别人。
- LLM_MODEL：模型名，例如 deepseek-v4-pro。
- PERMISSION_MODE：权限模式。

常用权限模式：

1. default
   读文件自动允许，写文件 / bash 等危险操作会询问。
   日常真实项目推荐用这个。

2. acceptEdits
   编辑类操作自动允许。
   沙盒或临时目录里推荐用这个，真实项目谨慎使用。

3. plan
   只规划，不执行危险写操作。
   想先看它怎么分析项目时使用。

4. bypassPermissions
   基本全自动放行。
   不推荐在真实项目使用。

五、启动方式 1：开发模式启动
----------------

开发调试时使用：

等价于：

优点：

六、启动方式 2：正式构建后启动
----------------

先构建：

等价于：

这是推荐的正式启动方式。


七、指定工作区启动
----------------

这个工具会把 Read / Write / Edit / Bash 等工具限制在 WORKSPACE_ROOT 指定的目录内。

例如，在项目自带沙盒目录里启动：

Git Bash：
WORKSPACE_ROOT="$(pwd)/sandbox" PERMISSION_MODE=acceptEdits npm start

PowerShell：
$env:WORKSPACE_ROOT = "$PWD\sandbox"
$env:PERMISSION_MODE = "acceptEdits"
npm start

CMD：
set WORKSPACE_ROOT=%cd%\sandbox
set PERMISSION_MODE=acceptEdits
npm start

如果不设置 WORKSPACE_ROOT，默认使用当前启动命令所在目录。


八、第一次推荐的真机联调流程
----------------

1. 创建或使用 sandbox 目录

项目里已经有一个 sandbox 示例目录：

sandbox/
  README.md
  package.json
  src/math.js

2. 用 acceptEdits 在沙盒里启动

Git Bash：
WORKSPACE_ROOT="$(pwd)/sandbox" PERMISSION_MODE=acceptEdits npm start

3. 输入一个简单任务，例如：

Read src/math.js, then add a new exported function divide(a,b) that returns a/b. Use the edit tool. Keep existing functions.

4. 观察它是否：
- 先调用 read 工具读取文件
- 再调用 edit 工具修改文件
- 输出工具耗时和 diff
- 最后总结修改内容

5. 检查文件是否真的改了：

cat sandbox/src/math.js


九、日常真实项目使用建议
----------------

如果要在你的真实项目里使用，建议这样做：

1. 先进入真实项目目录

cd 你的项目路径

2. 确认项目是干净状态

如果是 git 项目，先执行：

git status

最好在干净工作区使用，或者先提交当前修改。

3. 从 claude_personal 项目启动 CLI，并把 WORKSPACE_ROOT 指向真实项目

Git Bash 示例：
cd C:\Users\20616\Desktop\claude_compare\claude_personal
WORKSPACE_ROOT="C:/你的/真实/项目路径" PERMISSION_MODE=default npm start

真实项目推荐 PERMISSION_MODE=default，不推荐 acceptEdits 或 bypassPermissions。

4. 先让它只读分析，例如：

先阅读项目结构，告诉我这个项目的主要模块和启动方式，不要修改任何文件。

5. 再逐步给它小任务，例如：

读取 src/xxx.ts，帮我分析这个 bug 的原因。先不要改代码。

确认分析正确后，再让它改：

现在按你的方案修改，但每次 edit 前先说明要改哪里。


十、CLI 内置命令
----------------

启动后可以输入 slash command：

/help
显示可用命令。

/clear
清空当前对话上下文。

/model
显示当前模型。

/model 模型名
切换当前模型，例如：
/model deepseek-v4-pro

/compact
手动压缩上下文。

/tokens
显示当前上下文消息数量。

exit
退出程序。


十一、@文件引用
----------------

你可以在输入里直接引用文件：

帮我看一下 @src/math.js 这个文件有没有问题

工具会自动读取这个文件内容并附加到上下文里。

注意：
- 只能引用 WORKSPACE_ROOT 内的文件。
- 不能通过 ../ 逃逸到工作区外。

十三、常见问题
----------------

1. 启动时报 LLM_API_KEY is not set

说明 .env 没有配置 LLM_API_KEY，或当前目录不是 claude_personal 项目根目录。

解决：
cd C:\Users\20616\Desktop\claude_compare\claude_personal
确认 .env 存在并包含 LLM_API_KEY。

2. Provider 认证失败 / 403 / 401

检查：
- LLM_PROVIDER 是否正确
- LLM_API_KEY 是否正确
- LLM_MODEL 是否是该 provider 支持的模型
- baseURL 是否正确
- 账号额度是否可用

3. 工具不能修改文件

可能原因：
- PERMISSION_MODE=plan
- 文件不在 WORKSPACE_ROOT 内
- 还没有先 Read 就 Edit（本项目现在要求 Read 后才允许 Edit）

解决：
先让它 read 目标文件，再 edit。

4. 真实项目怕误改

使用：
PERMISSION_MODE=default

并先让它分析，不要直接让它修改。

5. 想快速验证 CLI 不崩

可以使用管道冒烟测试：

Git Bash：
printf 'reply with exactly PONG\nexit\n' | WORKSPACE_ROOT="$(pwd)/sandbox" PERMISSION_MODE=acceptEdits node dist/cli.js

看到 PONG 和 Goodbye! 就说明基础链路正常。

十五、安全建议
----------------

- 不要把 .env 提交到 git。
- 真实项目先用 default 或 plan 模式。
- 大范围改动前先 git commit 或备份。
- 优先让它先 Read / Grep / Glob 分析，再 Edit。
- 不要在 bypassPermissions 模式下指向重要目录。
