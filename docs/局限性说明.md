# 局限性说明

当前版本 v1.6.1，更新于 2026-10-08。以下边界描述本项目当前实现；历史报告中的完成度评分和测试数量不作为当前承诺。

- 官方订阅认证、托管云端、Remote Control、Chrome 官方扩展、IDE 客户端界面、语音服务和 Mods 运行时未移植。MCP 与 SDK 是公开接入方式。
- 通用 LSP 需要安装对应语言服务器。TypeScript / JavaScript 使用 tsserver；仅安装生产依赖时需另行安装 `typescript`。
- TypeScript 和 Python 接口使用本项目的 CLI 协议，不完整复现官方 Agent SDK 的全部控制消息和审批回调。
- 模型效果随 provider、模型与任务变化。单元测试和模拟集成测试不能证明真实编码效果等同官方。
- 多模态输入支持 PNG/JPEG/GIF/WebP 图片及 PDF。PDF 使用本地 PDF.js 提取文字并渲染为 PNG 页图，避免向兼容接口发送不受支持的原生 PDF；每次最多 5 页，默认前 5 页，通过 Read 的 `pages`（如 `"6-10"`）继续读取。PDF 最大 20 MiB，单张图片最大 5 MiB，每批 PDF 页图合计最大 5 MiB；本地 PDF 处理超过 30 秒会终止并返回工具错误。页图最长边 1568 像素、最多约 200 万像素，小字和复杂图纸可能需要局部截图。
- 已知纯文本模型只接收 PDF 中可提取的文字，无法识别扫描页或流程图；其他自定义模型或中转接口可通过 `LLM_SUPPORTS_IMAGES=false` 禁用图片，SDK 可设置 `options.supportsImages`。未知模型默认尝试图片输入，实际支持情况仍由接口决定。旧会话中的 PDF 附件在请求前自动转换，损坏附件以明确的未读取提示替代，不阻塞后续文字请求。
- 暂无音频、视频输入、语音识别或独立 OCR 引擎。扫描 PDF 的内容识别依赖视觉模型，不能因文字提取为空就视为已读懂。
- token 估算、价格配置和累计预算不能替代供应商账单的硬限制；错误响应没有 usage 时采用保守预留估算。
- 配置支持常用标准字段，未消费的顶层设置会报告诊断，不承诺官方全部字段与动态行为兼容。
- 会话快照与运行状态分别保存，不构成跨文件事务。历史结果和中断状态可以恢复，后台进程不会自动复活。
- `/loop` 在程序运行时执行，关闭程序期间不执行；恢复与错过任务策略见 [循环管理](loop-management.md)。
- 磁盘扩展沿用安装即信任；原生沙箱采用 best-effort 降权，降级会告警，不承诺文件系统 jail。
- 文件回退覆盖文件工具可追踪的修改，手动编辑和 Bash 修改不保证还原。

安装与配置见 [快速开始](快速开始.md)，自动化和 SDK 接口见 [深度使用指南](深度使用指南.md)。
