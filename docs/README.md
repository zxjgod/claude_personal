## 文档命名

- 更新日志：`YYYYMMDD-英文短横线主题.md`，使用小写英文或拼音；当前与归档记录采用同一规则。
- 有明确记录日期的报告、计划和评估：`YYYYMMDD-主题.md`。保留原主题语言、版本号和分册序号，日期统一前置，分隔符使用短横线。
- 仅能确认年月的文档：`YYYYMM-主题.md`，不补造具体日。既有 `202609-` 快照保持月份精度。
- 日期依据标题、明确的日期字段或原文件名；计划使用制定日期，报告使用记录日期，持续追加的记录使用起始日期。日期矛盾或只有正文引用、未来计划日期时保留原名。
- 固定入口与持续维护的文档保持稳定名称，包括 `README.md`、`CHANGELOG.md`、`_模板.md`、使用指南、当前架构、项目总览、维护方案和设计决策。正文中的最后更新时间继续维护，文件名不随每次修改改变。`CHANGELOG.md` 也是构建与 `/release-notes` 的固定读取入口。
- 不根据磁盘修改时间、模型猜测或引用的 API 版本补日期；`phase3-tool-refactor-plan.md`、`安全边界更新.md`、`bash-deadlock-analysis.md` 等缺少自身日期的文件保持原名。
- 重命名必须同步 Markdown 链接、索引、正文路径及源码注释中的文档引用。
