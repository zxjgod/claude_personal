## 一、实际测试过程

### 1. 官方 Claude Code

执行：

```bash
claude --version
```

结果：

```text
2.1.183 (Claude Code)
```

简单问答：

```bash
claude -p "请用一句中文回答：2+2 等于几？"
```

结果：

```text
2+2 等于 4。
```

读取项目文件：

```bash
claude -p "请读取 package.json，告诉我这个项目的 npm start 命令是什么。只回答命令。" --allowedTools "Read"
```

结果：

```text
`node dist/cli.js`
```

Slash command 测试：

```bash
printf '/help\n/exit\n' | timeout 40 claude
```

结果：

```text
/help isn't available in this environment.
```

补充观察：在 Git Bash 中直接执行 `claude -p "/help"`，`/help` 会被 MSYS 转成类似 `C:/Program Files/Git/help` 的路径。这是 Windows Git Bash 的路径转换坑，不代表官方 Claude Code 在真实 TTY 交互里的正常行为。

### 2. 当前项目 claude_personal

简单问答：

```bash
printf '请用一句中文回答：2+2 等于几？\nexit\n' | WORKSPACE_ROOT="$(pwd)/sandbox" PERMISSION_MODE=default npm start
```

结果摘要：

```text
Provider: deepseek
Model: deepseek-v4-pro
Tools loaded: 11

> 2+2 等于 4。
[tokens: 3963 in / 35 out]
Goodbye!
```

Slash command：

```bash
printf '/help\nexit\n' | WORKSPACE_ROOT="$(pwd)/sandbox" PERMISSION_MODE=default npm start
```

结果摘要：

```text
Commands:
  /help
  /clear
  /model
  /compact
  /tokens
  @<path>
  exit
```

读取工具调用：

```bash
printf '请读取 src/math.js，列出其中导出的函数名。\nexit\n' | WORKSPACE_ROOT="$(pwd)/sandbox" PERMISSION_MODE=default npm start
```

结果摘要：

```text
🔧 read — .../sandbox/src/math.js
✅ read (1ms)
  1: export function add(a, b) {
  ...

导出了 add / subtract / multiply
[tokens: 8113 in / 185 out]
Goodbye!
```

@文件引用：

```bash
printf '请根据 @src/math.js 用一句话总结这个文件。\nexit\n' | WORKSPACE_ROOT="$(pwd)/sandbox" PERMISSION_MODE=default npm start
```

结果摘要：

```text
📎 attached @src/math.js (150 bytes)
🔧 read — .../sandbox/src/math.js
✅ read (1ms)
该文件是一个 ES 模块，导出了 add、subtract、multiply 三个基础的算术运算函数。
```

观察：`@src/math.js` 已经把文件内容注入上下文，但模型仍然又调用了一次 `read`。这说明 @file 功能可用，但提示策略还需要优化，避免重复读取和浪费 token。

## 五、当前项目最影响体验的差距

### 1. 启动太像开发工具，不像产品

当前启动输出：

- banner
- provider
- model
- workspace
- permission mode
- recent incomplete sessions
- tools loaded

这些信息调试时有用，但日常使用会显得啰嗦。

建议：

- 增加 `--quiet` 或默认简洁模式。
- recent sessions 只在 `/sessions` 或启动参数里展示。
- token 统计改成可配置显示。

---

### 2. @file 会重复触发 read

本次测试：

```text
📎 attached @src/math.js
🔧 read — src/math.js
```

说明 @file 已注入内容，但模型仍然选择读文件。

建议：

- 在 user message 中明确加：
  `The following file contents have already been attached; do not call read unless you need fresh line-numbered content.`
- 或者把 @file 注入包装成更强的结构化上下文。

---

### 3. Slash command 数量少

当前只有：

- /help
- /clear
- /model
- /compact
- /tokens

建议增加：

- /sessions
- /resume
- /workspace
- /permission
- /tools
- /doctor
- /cost

---

### 4. UI 还不是 TUI

当前是 line-based CLI，已经比裸文本好很多，但离官方 Claude Code 的视觉体验还有距离。

建议：

- 增加 spinner / live status
- 更好的 markdown 渲染
- 折叠长工具结果
- 支持快捷键
- 支持 Ctrl+C 当前轮中断后保留 session

---

### 5. 错误恢复还有空间

已修：

- EOF / Ctrl+D / 管道输入耗尽导致崩溃
- SDK error object dump

仍建议：

- provider 失败时给出 `/doctor` 建议
- auth/baseURL/model 错误分类更细
- 网络错误自动提示检查代理

## 七、结论

本轮实际体验后，结论是：

1. **官方 Claude Code 仍然明显更成熟**：启动、UI、slash command、权限、会话管理、模型质量都更产品化。
2. **claude_personal 已经从“架构复刻”进入“可真实使用”阶段**：DeepSeek provider 下能完成真实 read/edit 工具循环。
3. **当前主要差距是 UX polish，不是核心能力**：核心 agent loop、tools、provider、permission、context、tests 都已经搭起来了。
4. **最优先的下一步不是再堆功能，而是打磨日常使用体验**：quiet 模式、@file 去重、/doctor、session 管理、工具结果折叠。

一句话评价：

> 官方 Claude Code 像成熟 IDE 插件/终端产品；当前 claude_personal 已经像一个能干活的本地 AI coding assistant 原型，下一阶段应该从“能用”打磨到“爱用”。
