## 二、努力程度定义（必须写入文档并作为 `/effort` 说明来源）

M38 后，`/effort` 的每个模式采用下面的产品语义定义。供应商 API 参数只是底层映射，不等同于用户可见定义。

| 努力程度 | 明确定义 | 典型行为边界 | 供应商参数映射原则 |
|---|---|---|---|
| `low` | 低努力：优先快速响应，只做必要推理，适合明确、局部、低风险任务 | 不主动扩展调查范围；少量文件内的直接修改；遇到不确定性时尽快向用户暴露 | Anthropic native 传 low；OpenAI-compatible 传 low |
| `medium` | 中等努力：默认平衡模式，在速度和可靠性之间取中，适合常规编码、解释和小型排障 | 会做必要上下文核查；不会为低风险任务开启大范围搜索；实现前后做基本验证 | Anthropic native 传 medium；OpenAI-compatible 传 medium |
| `high` | 高努力：更重视正确性，适合跨文件变更、复杂 bug、架构影响较明显的任务 | 会更系统地阅读相关代码；优先补足边界条件；验证覆盖更完整 | Anthropic native 传 high；OpenAI-compatible 传 high |
| `xhigh` | 超高努力：面向高复杂度或高风险任务，在 `high` 基础上增加更深入的因果分析与反例检查 | 会主动寻找隐藏约束、回归风险和替代路径；适合权限、持久化、并发、状态同步类改动 | Anthropic native 传 xhigh（若支持）；OpenAI-compatible 降级为 high，并在说明中标注参数层塌缩 |
| `max` | 最大努力：单代理内的最高深度模式，适合需要尽量穷尽边界、严谨实现和完整验证的任务 | 会更倾向于先建计划、再实施、再验证；对安全/权限/数据删除类变更执行更严格检查 | Anthropic native 传 max（若支持）；OpenAI-compatible 降级为 high，并保留产品层 max 语义 |
| `ultracode` | 极限编排：不只是更高 reasoning，而是倾向于使用多代理/工作流进行广覆盖探索、设计、实现审查与反向验证 | 适合大型迁移、复杂审计、需要多视角验证的任务；代价是更慢、更耗 token | 供应商 reasoning 参数按最高可用档处理；额外语义由本应用的 agent/workflow 策略承担 |

验收要求：`/effort` 无参数展示上述定义摘要；`/effort <level>` 设置后输出该 level 的定义、适用场景和后端映射提示；相关文档同步保留完整表格。

## 四、明确不做（本轮边界）

- 不取消 `src/permissions.ts` 现有 bypass-immune 安全地板；`bypassPermissions` 不等于允许危险命令、敏感路径或破坏性路径。
- 不做 `/sessions clear-all` 或批量删除，避免误删历史会话。
- 不为 `/compact` 伪造真实 LLM token 级进度；只做可解释的阶段式进度条。
- 不改 Ink 依赖，不新增键盘解析库；当前 Ink 已支持 `key.tab && key.shift`。
- 不把 `/effort` 的产品层定义强行等同于所有供应商的底层 API 参数；后端不支持的档位必须透明降级说明。
- 不在本轮重构整个权限系统；只引入实时模式来源并保持既有 `checkPermission()` 为唯一权限判定入口。

## 五、风险与回退

| 风险 | 影响 | 缓解 / 回退 |
|---|---|---|
| 实时权限模式如果只更新 UI、不更新工具上下文，会造成显示与实际权限不一致 | 用户以为已切换，实际仍按旧模式执行 | 模式状态必须由权限检查读取；测试覆盖「切换后下一次工具调用」 |
| `bypassPermissions` 若被新的模式读取路径绕开安全地板，可能执行危险操作 | 安全事故 | 不改 `checkPermission()` 安全地板顺序；所有工具仍走统一权限入口 |
| `/sessions delete` 前缀匹配过宽导致误删 | 历史对话丢失 | 必须唯一匹配才删除；歧义时只展示候选，不执行 |
| `/compact` 进度条若依赖计时器测试，容易 flaky | CI 不稳定 | 进度渲染函数纯函数化，命令测试断言阶段文本而不是时间 |
| 两条 TUI 路径只改一条导致行为不一致 | 默认 TUI 与 fullscreen 体验分叉 | App 与 FullScreenApp 均纳入验收与测试 |
| `EnterPlanModeTool` 与 Shift+Tab 同时存在时状态冲突 | plan 状态错乱或退出失败 | 抽象统一 setter/getter；工具和键盘都调用同一模式状态接口 |
