## 🎯 1. ScheduleWakeup 工具

### 功能描述
为 `/loop` 动态模式提供自适应调度能力，支持智能延迟管理以优化提示缓存使用。

### 新增文件
- `src/tools/extended/schedule-wakeup.ts` — ScheduleWakeup 工具实现
- `src/__tests__/schedule-wakeup.test.ts` — 13 个测试 ✅

### 核心特性

#### API 签名
```typescript
ScheduleWakeup({
  delaySeconds: number,      // 60-3600s，延迟时间
  prompt: string,            // 唤醒后执行的提示
  reason: string,            // 显示给用户的原因（一句话）
  stop?: boolean             // true = 立即停止循环
})
```

#### 缓存优化策略
**Anthropic 提示缓存 TTL: 5 分钟**

```typescript
// 缓存策略分析
60-270s   (1-4.5 min)  → 缓存保持温热 ✅
300s      (5 min)      → ⚠️ 最差选择（付费但不摊销）
1200-1800s (20-30 min) → 摊销缓存未命中 ✅
```

**智能延迟选择**:
```typescript
// ✅ 好的选择
ScheduleWakeup({
  delaySeconds: 270,     // 主动轮询（CI 构建）
  prompt: "Check CI status",
  reason: "Waiting for build to complete"
})

ScheduleWakeup({
  delaySeconds: 1800,    // 空闲心跳
  prompt: "Continue work",
  reason: "Idle tick, no specific signal"
})

// ❌ 避免的选择
ScheduleWakeup({
  delaySeconds: 300,     // 正好 5 分钟 = 浪费
  prompt: "...",
  reason: "..."
})
```

#### 使用示例

**示例 1: 等待 CI 构建**
```typescript
// CI 构建通常需要 8 分钟
// 睡眠 270s × 2 = 9 分钟，缓存保持温热
ScheduleWakeup({
  delaySeconds: 270,
  prompt: "Check if CI build completed",
  reason: "Watching CI run (stay in cache)"
})
```

**示例 2: 空闲循环**
```typescript
// 没有特定信号，定期检查
ScheduleWakeup({
  delaySeconds: 1800,
  prompt: "Check for new work",
  reason: "Idle heartbeat, 30min amortize cache miss"
})
```

**示例 3: 停止循环**
```typescript
// 任务完成，停止循环
ScheduleWakeup({ stop: true })
// => Dynamic loop stopped. Cancelled 2 pending wakeup(s).
```

#### 缓存效率警告
工具会自动检测低效延迟：
```typescript
ScheduleWakeup({
  delaySeconds: 300,  // 正好 5 分钟
  prompt: "...",
  reason: "..."
})
// => ⚠️ Warning: 300s is cache-inefficient. 
//    Use 270s (stay warm) or 1200s+ (amortize miss).
```

### 与 CronCreate 的区别

| 特性 | ScheduleWakeup | CronCreate |
|-----|----------------|------------|
| **用途** | `/loop` 动态模式 | 定时任务 |
| **触发** | 单次唤醒 | 循环/一次性 |
| **调度** | 相对时间（延迟） | 绝对时间（cron） |
| **缓存优化** | ✅ 内置建议 | ❌ 无 |
| **持久化** | ❌ 会话级 | ✅ 可选 durable |

## 🎯 2. ReportFindings 工具

### 功能描述
为代码审查提供结构化输出，支持 UI 特殊渲染和验证级别标记。

### 新增文件
- `src/tools/extended/report-findings.ts` — ReportFindings 工具实现
- `src/__tests__/report-findings.test.ts` — 12 个测试 ✅

### 核心特性

#### API 签名
```typescript
ReportFindings({
  findings: Array<{
    file: string,              // 文件路径（repo-relative）
    line?: number,             // 行号（1-based，可选）
    summary: string,           // 一句话缺陷描述
    category: string,          // 类别 slug（kebab-case）
    failure_scenario: string,  // 具体的失败场景
    verdict?: "CONFIRMED" | "PLAUSIBLE",  // 验证级别
    outcome?: "fixed" | "skipped" | "no_change_needed"  // 修复结果
  }>,
  level?: "low" | "medium" | "high" | "xhigh" | "max"  // 审查级别
})
```

#### 数据结构

**CodeFinding** — 单个发现：
```typescript
interface CodeFinding {
  file: string;              // 必需
  line?: number;             // 可选
  summary: string;           // 必需
  category: string;          // 必需（建议：correctness, security, 
                            //       simplification, efficiency, test-coverage）
  failure_scenario: string;  // 必需（具体输入 → 错误输出）
  verdict?: FindingVerdict;  // 可选（CONFIRMED/PLAUSIBLE）
  outcome?: FindingOutcome;  // 可选（fixed/skipped/no_change_needed）
}
```

**FindingsReport** — 完整报告：
```typescript
interface FindingsReport {
  findings: CodeFinding[];
  level?: "low" | "medium" | "high" | "xhigh" | "max";
  reportedAt: bigint;
}
```

**场景 1: 初次审查报告**

### ReportFindings 实现要点

**1. 会话隔离存储**
```typescript
const FINDINGS_REGISTRY = new Map<string, FindingsReport[]>();

export function recordFindings(sessionId: string, report: FindingsReport) {
  const reports = FINDINGS_REGISTRY.get(sessionId) ?? [];
  reports.push(report);
  FINDINGS_REGISTRY.set(sessionId, reports);
}
```

**2. 格式化输出**
```typescript
for (let i = 0; i < findings.length; i++) {
  const f = findings[i];
  const location = f.line ? `${f.file}:${f.line}` : f.file;
  const verdict = f.verdict ? ` [${f.verdict}]` : "";
  const outcome = f.outcome ? ` → ${f.outcome}` : "";
  
  lines.push(`${i+1}. [${f.category}] ${location}${verdict}${outcome}`);
```

## 🚀 使用场景示例

### 场景 1: /loop 动态模式

```typescript
// Agent 主循环
while (true) {
  // 执行工作
  const result = await doWork();
  
  if (result.needsWait) {
    // 等待外部信号（CI 构建）
    ScheduleWakeup({
      delaySeconds: 270,  // 4.5 分钟，保持缓存
      prompt: "Check CI status and continue",
      reason: "Waiting for CI build"
    });
    break;
  }
  
  if (result.idle) {
    // 空闲状态
    ScheduleWakeup({
      delaySeconds: 1800,  // 30 分钟心跳
      prompt: "Check for new work",
      reason: "Idle heartbeat"
    });
    break;
  }
  
  if (result.done) {
    // 完成工作
    ScheduleWakeup({ stop: true });
    break;
  }
}
```

### 场景 2: 代码审查工作流

```typescript
// 1. 执行代码审查
const issues = await reviewCode({
  files: ["src/**/*.ts"],
  level: "high"
});

// 2. 报告发现
ReportFindings({
  findings: issues.map(issue => ({
    file: issue.file,
    line: issue.line,
    summary: issue.message,
    category: issue.severity,
    failure_scenario: issue.scenario,
    verdict: issue.verified ? "CONFIRMED" : "PLAUSIBLE"
  })),
  level: "high"
});

// 3. 修复问题
for (const issue of issues) {
  await fixIssue(issue);
}

// 4. 重新报告（标记修复状态）
ReportFindings({
  findings: issues.map(issue => ({
    ...issue,
    outcome: "fixed"
  })),
  level: "high"
});
```
