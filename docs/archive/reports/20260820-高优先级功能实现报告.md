## 🎯 1. Agent 工具

### 功能描述
提供与官方 Claude Code 完全兼容的 `Agent` 工具 API，作为现有 `Task` 工具的增强版本。

### 新增文件
- `src/tools/extended/agent.ts` — Agent 工具实现

### 核心特性

#### API 签名
```typescript
Agent({
  prompt: string,                    // 任务指令（必需）
  description?: string,              // 任务简短描述
  subagent_type?: string,           // Agent 类型（可选，省略则 fork）
  model?: string,                    // 模型覆盖
  effort?: "low" | "medium" | "high" | "xhigh" | "max",  // 推理努力级别
  isolation?: "worktree",           // Git worktree 隔离（新特性）
  run_in_background?: boolean       // 后台运行
})
```

#### 关键实现

**1. Worktree 隔离支持**
```typescript
if (input.isolation === "worktree") {
  // 自动创建临时 git worktree
  // 在隔离环境中运行 agent
  // 成功后自动清理
}
```

**2. 模型和努力级别覆盖**
```typescript
let modelConfig = context.modelConfig;
if (input.model || input.effort) {
  modelConfig = {
    ...modelConfig,
    ...(input.model && { model: input.model }),
    ...(input.effort && { effort: input.effort }),
  };
}
```

**3. Fork 模式兼容**
- 当 `subagent_type` 省略时，继承父 agent 上下文
- 复用提示缓存，提升性能

### 与 Task 工具的关系
- `Agent` 是官方 API 名称
- `Task` 保留作为内部实现
- `Agent` 工具使用 `aliases: ["agent"]` 注册
- 两者功能互补，`Agent` 提供更多高级选项

## 🎯 2. 结构化任务追踪系统

### 功能描述
完整的项目管理风格的任务追踪系统，支持状态管理、依赖关系和元数据。

### 新增文件
- `src/structured-tasks.ts` — 核心任务管理逻辑
- `src/tools/extended/structured-task-tools.ts` — 工具接口
- `src/__tests__/structured-tasks.test.ts` — 单元测试（17 个测试）

### 核心特性

#### 1. TaskCreate — 创建任务
```typescript
TaskCreate({
  subject: string,           // 简短标题（祈使句）
  description: string,       // 详细描述
  activeForm?: string,       // 进行中时的显示文本
  metadata?: Record<string, unknown>
})
```

**示例**：
```typescript
TaskCreate({
  subject: "Fix authentication bug",
  description: "The login endpoint returns 500 when...",
  activeForm: "Fixing authentication bug",
  metadata: { priority: "high", assignee: "alice" }
})
// => Created task 1: Fix authentication bug
```

#### 2. TaskGet — 获取任务详情
```typescript
TaskGet({ taskId: string })
```

**返回**：
```
Task 1: Fix authentication bug
Status: pending
Description: The login endpoint returns 500 when...
Blocks: 3
Blocked By: (none)
Metadata: {"priority":"high"}
```

#### 3. TaskUpdate — 更新任务
```typescript
TaskUpdate({
  taskId: string,
  status?: "pending" | "in_progress" | "completed" | "deleted",
  subject?: string,
  description?: string,
  owner?: string,
  metadata?: Record<string, unknown>,
  addBlocks?: string[],        // 此任务阻塞的任务 ID
  addBlockedBy?: string[]      // 阻塞此任务的任务 ID
})
```

**状态机**：
```
pending → in_progress → completed
   ↓
deleted (任何状态可直接删除)
```

**依赖管理**：
```typescript
// Task 1 必须在 Task 2 之前完成
TaskUpdate({ taskId: "2", addBlockedBy: ["1"] })
TaskUpdate({ taskId: "1", addBlocks: ["2"] })
```

#### 4. TaskList — 列出所有任务
```typescript
TaskList()
```

**输出示例**：
```
Tasks (3):
1. [pending] Setup database (owner: alice)
2. [in_progress] Implement API [blocked by: 1]
3. [completed] Write tests
```

### 数据结构

```typescript
interface StructuredTask {
  id: string;                // 唯一 ID（数字字符串）
  subject: string;           // 标题
  description: string;       // 详细描述
  activeForm?: string;       // 进行中显示文本
  status: TaskStatus;        // 状态
  owner?: string;            // 所有者
  metadata?: Record<string, unknown>;  // 自定义元数据
  blocks: string[];          // 阻塞的任务 ID 列表
  blockedBy: string[];       // 被阻塞的任务 ID 列表
  createdAt: bigint;         // 创建时间戳
  updatedAt: bigint;         // 更新时间戳
}
```

### 会话隔离
- 每个会话维护独立的任务注册表
- 任务 ID 在会话内唯一
- 跨会话任务不可见

- `src/__tests__/cron-shared.test.ts` — 单元测试（17 个测试）

### 架构重构
**重构前**：
- `ScheduleCron` 工具独立实现
- 逻辑嵌入在 `m9.ts` 中
- 无法复用

**重构后**：
```
cron-shared.ts (核心逻辑)
    ↓
    ├── m9.ts (ScheduleCron 使用共享逻辑)
    └── cron-tools.ts (CronCreate/Delete/List)
```

### 核心特性

#### 1. CronCreate — 创建定时任务
```typescript
CronCreate({
  cron: string,              // 5 字段 cron 表达式（本地时区）
  prompt: string,            // 触发时执行的提示
  recurring?: boolean,       // true=循环，false=一次性（默认 true）
  durable?: boolean          // true=持久化，false=会话级（默认 false）
})
```

**示例**：
```typescript
// 工作日每天 9 点
CronCreate({
  cron: "0 9 * * 1-5",
  prompt: "Run daily standup report",
  recurring: true,
  durable: true
})
// => Scheduled recurring job job-abc123-1
//    Cron: "0 9 * * 1-5" (durable)
```

**Cron 表达式格式**：
```
分钟 小时 日期 月份 星期
 M   H   DoM Mon DoW

示例：
"0 9 * * *"      — 每天 9:00
"*/5 * * * *"    — 每 5 分钟
"30 14 1 * *"    — 每月 1 日 14:30
"0 0 * * 0"      — 每周日午夜
"0-30 9-17 * * 1-5" — 工作日 9-17 点，每小时前 30 分钟
```

#### 2. CronDelete — 取消定时任务
```typescript
CronDelete({ id: string })
```

**示例**：
```typescript
CronDelete({ id: "job-abc123-1" })
// => Job job-abc123-1 cancelled and removed.
```

- 从会话内存中移除
- 如果是持久化任务，也从 `.claude/scheduled_tasks.json` 中删除

#### 3. CronList — 列出所有任务
```typescript
CronList()
```

**输出示例**：
```
Scheduled jobs (3):
job-abc123-1: "0 9 * * 1-5" [recurring, durable]
job-abc123-2: "30 14 25 12 *" [one-shot, session-only]
job-abc123-3: "*/30 * * * *" [recurring, session-only]
```

### Cron 表达式验证

`validateCron()` 函数提供严格的语法检查：

```typescript
validateCron("0 9 * * *")     // null (有效)
validateCron("60 9 * * *")    // "Field 1 (60): value out of range 0-59"
validateCron("0 9 *")         // "Cron must have exactly 5 fields"
validateCron("abc 9 * * *")   // "Field 1 (abc): not a number, range, or *"
```

**验证规则**：
- 必须是 5 个字段
- 分钟: 0-59
- 小时: 0-23
- 日期: 1-31
- 月份: 1-12
- 星期: 0-7（0 和 7 都是周日）
- 支持范围 (`1-5`)、列表 (`1,3,5`)、步长 (`*/5`)

## 🎨 设计决策

### 1. Agent 工具实现方式
**决策**: 独立实现而非简单别名

**理由**:
- 需要支持 `isolation: "worktree"` 特性
- 需要支持 `effort` 参数
- 需要更细粒度的模型覆盖控制
- 保持与官方 API 的完全兼容

### 2. 结构化任务命名
**决策**: 使用 `TaskCreate/Get/Update/List` 而非 `StructuredTaskXxx`

**理由**:
- 与官方 Claude Code API 完全一致
- 简洁明了
- 通过工具描述区分用途（任务管理 vs 子 agent 执行）

### 3. Cron 逻辑共享
**决策**: 提取共享模块 `cron-shared.ts`

**理由**:
- 避免代码重复
- 便于测试
- 支持向后兼容（`ScheduleCron` 和 `CronCreate` 使用同一底层）
- 统一任务注册表，工具间可互操作

### 4. 会话隔离
**决策**: 所有状态按 `sessionId` 隔离

**理由**:
- 多会话安全
- 防止数据泄漏
- 符合现有架构模式

## 🚀 使用示例

### 示例 1: Agent 工具 + Worktree 隔离
```typescript
// 在隔离的 worktree 中重构代码，避免污染主工作树

  prompt: "Refactor auth module to use async/await",
  description: "Async refactor",
  isolation: "worktree",

})
```

### 示例 2: 结构化任务管理工作流
```typescript
// 1. 创建任务
const setup = TaskCreate({
  subject: "Setup database schema",
  description: "Create tables for users, posts, comments",
  metadata: { priority: "high" }
})

const api = TaskCreate({
  subject: "Implement REST API",
  description: "CRUD endpoints for all resources"
})

// 2. 设置依赖（API 依赖数据库）

// 6. 继续下一个
```
