## 技术栈

| 类别 | 选型 |
|------|------|
| 语言 | TypeScript (ES2022, NodeNext) |
| 运行时 | Node.js |
| LLM SDK | `openai` (OpenAI 兼容)、`@anthropic-ai/sdk` (Anthropic 原生) |
| MCP | `@modelcontextprotocol/sdk` |
| CLI | `commander` |
| 终端渲染 | `chalk`、`marked`、自定义 ANSI |
| TUI | `ink` + `react` + `useSyncExternalStore` |
| 文件匹配 | `fast-glob` |
| 测试 | `vitest` |
| 构建 | `tsc` |

## 整体架构

```
CLI 入口 (cli.ts)
    │
    ├── 参数解析 / .env 加载 / 配置
    ├── 构建系统提示 (system-prompt.ts)
    ├── 装配工具 (tools.ts → CORE_TOOLS + MCP)
    │       └── 工具注册中心 (tool-registry.ts)
    │
    ├── 主 REPL 循环
    │       ├── 斜杠命令 (commands.ts) ── 本地处理
    │       ├── 文件引用展开 (file-refs.ts)
    │       └── Agent 循环 (agent-loop.ts) ── LLM 驱动
    │               │
    │               ├── LLM 调用 (llm-adapter.ts)
    │               │       ├── OpenAI 兼容路径
    │               │       ├── Anthropic 路径 (anthropic-adapter.ts)
    │               │       └── 云网关路由 (cloud-gateway.ts)
    │               │
    │               ├── 工具执行 + 权限检查 (permissions.ts)
    │               ├── Hooks 拦截 (hooks.ts)
    │               ├── 上下文压缩 (context-snip.ts)
    │               └── 预测性预取 (speculation.ts)
    │
    └── 终端呈现 (cli-renderer.ts / cli-spinner.ts / markdown.ts)
```

## 模块清单

### 1. 入口与 CLI 层

#### `src/cli.ts`
- **职责**: CLI 入口点 —— 解析参数、加载 .env、构建 system prompt、装配工具与 MCP、运行主 REPL 循环、处理斜杠命令与文件引用、全局错误兜底。
- **主要导出**: `main()` (入口,由 shebang 直接执行)
- **依赖**: 几乎所有模块 —— agent-loop、system-prompt、commands、llm-adapter、mcp、cli-input、cli-renderer、cli-spinner、cli-errors、file-refs、git-context、hooks

#### `src/index.ts`
- **职责**: 包的主入口/聚合导出 —— 统一 re-export 全部公共 API (类型、agent loop、命令、工具、hooks、adapter、permissions、MCP、persistence)。
- **主要导出**: 聚合 re-export (types、agentLoop、handleSlashCommand、CORE_TOOLS、HookRegistry、anthropicCaller、createModelCaller、MCPManager、PersistenceManager 等)
- **依赖**: 几乎所有子模块

#### `src/commands.ts`
- **职责**: 斜杠命令 (/ 开头) —— 在 LLM 之前本地处理,可修改会话状态 (messages/model) 并直接打印;未匹配则提示 /help。
- **主要导出**: `handleSlashCommand`、`COMMANDS` (命令数组)、`COMMAND_MAP`;类型 `CommandContext`、`CommandResult`、`SlashCommand`
- **依赖**: change-tracker、git-context、effort、mcp、persistence、lsp、fs、path、chalk

#### `src/cli-input.ts`
- **职责**: readline 包装器 —— 提供 EOF 安全、支持管道多行输入的问答/读取语义,处理 `>` 续行与代码围栏。
- **主要导出**: `createCliInputReader()` (返回 `{ askQuestion, readInput, isClosed }`)
- **依赖**: `node:readline`

#### `src/cli-interactive.ts`
- **职责**: TTY 专用 raw-mode 输入框 —— 绘制带边框的 `>` 提示框、`/` 斜杠命令自动补全下拉、带边框的 Yes/No 权限菜单,全部用 ANSI 光标原地重绘。
- **主要导出**: 交互输入框与权限菜单渲染函数 (如 `drawInputBox`、autocomplete 等)
- **依赖**: commands (斜杠命令列表)、chalk、ANSI 控制序列

#### `src/cli-renderer.ts`
- **职责**: 终端呈现辅助 —— 块缓冲 markdown 输出、工具进度/结果渲染 (●/⎿ 字形)、带边框权限菜单,把显示逻辑从 cli.ts 中剥离。
- **主要导出**: markdown 块渲染、tool progress/result 渲染、permission menu 渲染等函数
- **依赖**: markdown、chalk

#### `src/cli-spinner.ts`
- **职责**: "思考中"动画状态行 —— 循环 spinner 字形 + 颜色 shimmer 扫过动词 + 已用秒数 + 估算 token 数,原地 `\r` 重绘。
- **主要导出**: spinner 类/工厂 (渲染 `✶ Whisking… (16s · ↑ 144 tokens)` 形式)
- **依赖**: chalk

#### `src/cli-errors.ts`
- **职责**: 精简格式化 provider/SDK 错误为终端友好提示,避免泄漏密钥或打印庞大请求对象。
- **主要导出**: `formatCliError(error)`
- **依赖**: 无 (纯函数)

---

### 2. Agent 循环核心

#### `src/agent-loop.ts`
- **职责**: Agent 循环核心 —— 驱动"模型调用 → 工具执行 → 再调用"的迭代循环,包含权限检查、上下文压缩、自动 compaction、错误重试策略。
- **主要导出**: `agentLoop` (异步生成器,产出 LoopEvent)、`autoCompact` (自动压缩对话历史)
- **依赖**: types、permissions (checkPermission)、context-snip (snipContext)、hooks、工具与 read-tracker 等

---

### 3. LLM 适配层

#### `src/llm-adapter.ts`
- **职责**: 多 provider LLM 客户端适配 —— 内部格式↔OpenAI 消息转换、OpenAI 兼容流式 caller、工厂选择 anthropic 或 openAI 路径、错误检测助手、provider 配置解析 (含云网关路由)。
- **主要导出**: `createModelCaller`、`resolveProviderConfig`、`isRateLimitError`、`isContextLengthError`、`isAuthError`、`isProviderError`、`PROVIDER_CONFIGS`
- **依赖**: `openai`、anthropic-adapter、cloud-gateway、effort、types

#### `src/anthropic-adapter.ts`
- **职责**: 将项目内部 OpenAI 风格的消息/工具格式转换为 Anthropic Messages API 原生格式,启用 prompt caching 与精确流式 usage,保持 agent loop 与 provider 无关。
- **主要导出**: `anthropicCaller` (ModelCaller)、`convertMessagesToAnthropic`、`formatSystemForAnthropic`、`formatToolsForAnthropic`
- **依赖**: `@anthropic-ai/sdk`、effort、types

#### `src/cloud-gateway.ts`
- **职责**: 云 provider 网关路由 —— 为 AWS Bedrock / Google Vertex AI 解析其 OpenAI 兼容端点 URL,复用现有 OpenAI 兼容流式 caller。
- **主要导出**: `isCloudGateway`、`resolveGateway`
- **依赖**: 无外部 (纯 URL 计算)

---

### 4. 系统提示构建

#### `src/system-prompt.ts`
- **职责**: 系统提示构建器 —— 6 个静态段 (身份、工具、环境、规则等) + 动态边界段 (git 状态、语言偏好)。
- **主要导出**: `buildSystemPrompt(options)`、`rebuildDynamicSections(...)`、`DYNAMIC_BOUNDARY` 常量、`SystemPromptOptions` 接口
- **依赖**: types (Tool)

---

### 5. 工具系统

#### `src/tool-registry.ts`
- **职责**: 工具注册中心 —— 管理所有可用工具的注册、查询、格式化,并提供 `createTool` 工厂统一默认值。
- **主要导出**: `ToolRegistry` 类 (`register`/`get`/`getAll`/`formatResult`)、`createTool<T>(config)` 工厂函数
- **依赖**: types

#### `src/tools.ts`
- **职责**: 核心工具实现 —— Read/Write/Edit/MultiEdit/Bash/Glob/Grep,以及聚合所有工具 (核心 + M8 + Team + M14) 为 `CORE_TOOLS`。
- **主要导出**: `ReadTool`、`WriteTool`、`EditTool`、`MultiEditTool`、`BashTool`、`GlobTool`、`GrepTool`、`CORE_TOOLS` (聚合数组)、辅助函数 `resolveInWorkspace`、`relForDisplay`、`statMtimeMs`
- **依赖**: fs、path、child_process、fast-glob、types、tool-registry、permissions、read-tracker、change-tracker、todo-tool、web-fetch、web-search、task-tool、tools-m8、tools-m8-interactive、tools-team、tools-m9

#### `src/tools-m8.ts`
- **职责**: M8 广度工具 —— NotebookEdit (Jupyter 单元格增删改)、LSP 诊断 (tsserver 优先,tsc 回退)、ToolSearch、MCP 资源读写。
- **主要导出**: `NotebookEditTool`、`LspDiagnosticsTool`、`createToolSearchTool(getTools)` 工厂、`createMcpResourceTools(provider)` 工厂
- **依赖**: fs、path、child_process、types、tool-registry、tools (辅助函数)、read-tracker、change-tracker、lsp-legacy、lsp

#### `src/tools-m8-interactive.ts`
- **职责**: M8 交互工具 —— EnterPlanMode/ExitPlanMode 运行时切换 permissionMode,AskUserQuestion 调用 CLI 提问。
- **主要导出**: `EnterPlanModeTool`、`ExitPlanModeTool`、`AskUserQuestionTool`
- **依赖**: types、tool-registry;AskUserQuestion 依赖 `context.askUserQuestion`

#### `src/tools-m9.ts`
- **职责**: M14 工具集 —— git worktree 隔离 (EnterWorktree/ExitWorktree)、Skill 调用、Cron 调度/Sleep、Windows PowerShell。
- **主要导出**: `EnterWorktreeTool`、`ExitWorktreeTool`、`SkillTool`、`ScheduleCronTool`、`SleepTool`、`PowerShellTool`、`M14_TOOLS` (聚合数组)
- **依赖**: path、child_process、types、tool-registry、skills

#### `src/tools-team.ts`
- **职责**: Team 工具集 —— 将 team.ts 的有状态多代理层暴露给主代理:创建团队、发消息、列出/查询/停止成员。
- **主要导出**: `TeamCreateTool`、`SendMessageTool` (支持 background)、`TaskListTool`、`TaskGetTool`、`TaskStopTool`、`TEAM_TOOLS` (聚合数组)
- **依赖**: types、tool-registry、subagents、team

#### `src/task-tool.ts`
- **职责**: Task 工具 —— 生成独立子代理执行多步任务,带可配置工具集、隔离上下文、信号量限流并发。
- **主要导出**: `TaskTool` (Tool,name=`task`)
- **依赖**: types、tool-registry (createTool)、subagents、system-prompt

#### `src/todo-tool.ts`
- **职责**: Todo 工具 —— LLM 维护结构化任务列表,每次全量替换,UI 渲染为进度追踪器。
- **主要导出**: `TodoTool` (Tool,name=`todo`)、`getTodos(sessionId)`、`clearTodos(sessionId)`
- **依赖**: types、tool-registry (createTool)

#### `src/web-fetch.ts`
- **职责**: WebFetch 工具 —— 抓取 URL、剥离 HTML、返回纯文本供 LLM 分析,带 SSRF 防护与大小/超时限制。
- **主要导出**: `WebFetchTool` (Tool,name=`web_fetch`)
- **依赖**: types、tool-registry;使用全局 `fetch`

#### `src/web-search.ts`
- **职责**: WebSearch 工具 —— 无需 API key,查询 DuckDuckGo HTML 端点,解析结果为 title/url/snippet。
- **主要导出**: `WebSearchTool` (Tool,name=`web_search`)、`parseSearchResults(html, limit)`
- **依赖**: types、tool-registry;使用全局 `fetch`

### 6. 权限与安全

#### `src/permissions.ts`
- **职责**: 权限系统 —— 4 种模式 (default/acceptEdits/bypassPermissions/plan) + 危险命令模式检测 + LLM 辅助风险分级。
- **主要导出**: `checkDangerousPattern(toolName, input, workspaceRoot)`、`isBlockedPath(filePath)`、`classifyPermissionRisk(...)`、`checkPermission(options)`
- **依赖**: path、types

#### `src/read-tracker.ts`
- **职责**: "先读后改"追踪器 —— 编辑文件前强制要求模型已读过且磁盘 mtime 未变,防止盲目编辑覆盖未见内容。
- **主要导出**: `markRead`、`checkReadBeforeEdit`、`refreshRead`、`resetReadTracker`
- **依赖**: 无外部依赖 (纯内存 Map)

---

### 7. 上下文管理

#### `src/context-snip.ts`
- **职责**: 基于重要性的无损预压缩 —— 在 LLM 摘要式 autoCompact 之前,就地修剪最庞大、最旧的工具结果 (head + tail 摘录 + snipped 标记),保留最近消息与非工具消息不动。
- **主要导出**: `snipContext`、`SNIP_MARKER`、`SnipOptions`、`SnipResult`
- **依赖**: types (Message)

#### `src/speculation.ts`
- **职责**: 预测性工具预取 —— 搜索类工具 (grep/glob) 返回路径后,后台预读这些文件并缓存,后续 Read 命中缓存。
- **主要导出**: `SpeculationCache` 类 (`prefetch`/`tryConsume`)、`rankPaths`、`predictReads`、`formatSpeculationLine`
- **依赖**: types (ToolResult)

---

### 8. 子代理与团队

#### `src/subagents.ts`
- **职责**: 子代理类型注册表 —— 每种类型声明可用核心工具与系统提示,Task 工具按名解析并在隔离 loop 中运行。
- **主要导出**: `SubagentType` 接口、`registerSubagentType`、`getSubagentType`、`listSubagentNames`、`resolveSubagentTools`、`setCoreToolsForSubagents`
- **依赖**: types (Tool);`getCoreToolsForSubagents` 动态 import tools

#### `src/team.ts`
- **职责**: 有状态多代理协作 (Team) —— 命名代理跨消息持久化,各自保留历史与状态,支持点对点编排。
- **主要导出**: `createAgents`、`getAgent`、`listAgents`、`stopAgent`、`runAgentTurn`、`resetTeams`
- **依赖**: types;运行时通过 `getCoreToolsForSubagents` 间接依赖 tools

---

### 9. MCP 集成

#### `src/mcp.ts`
- **职责**: MCP 集成 —— 连接外部 MCP 服务器 (stdio/http/sse/ws)、发现工具并包装为原生 Tool 对象供 agent loop 使用;含超时保护、OAuth 授权触发、首次调用交互确认、资源列举/读取。
- **主要导出**: `MCPManager` 类、`discoverMCPConfigs`、`withTimeout`、`TimeoutError`;类型 `MCPServerConfig`、`MCPConfig`、`MCPTransportType`
- **依赖**: `@modelcontextprotocol/sdk`、mcp-auth、types、fs/path/os

#### `src/mcp-auth.ts`
- **职责**: MCP OAuth 2.0 授权 —— 文件持久化的 OAuthClientProvider,token/client 注册/PKCE verifier 存于 `~/.claude/mcp-auth/`,启动 localhost 回调服务器捕获授权码,跨运行保持授权。
- **主要导出**: `FileTokenOAuthProvider` 类;接口 `MCPOAuthConfig`
- **依赖**: fs、path、os、http、`@modelcontextprotocol/sdk`

---

### 10. 持久化与遥测

#### `src/persistence.ts`
- **职责**: 会话持久化 —— 将对话历史以 JSON 文件保存到 `.claude/sessions/<id>.json`,支持原子写入与并发安全。
- **主要导出**: `PersistenceManager` 类 (`save`/`load`/`loadSync`/`listSessions`/`deleteSession`/`generateId`);接口 `SessionData`、`SessionMeta`
- **依赖**: fs、path、crypto、types (Message)

#### `src/session-stats.ts`
- **职责**: 累计 token 用量与尽力成本估算,供 `/cost`、`/status`、`/context` 报告会话级总量。
- **主要导出**: `SessionStats` 类、`lookupPricing(model)`、`estimateCost(...)`、`formatUsd`、`formatDuration`
- **依赖**: 无外部依赖 (静态定价表)

#### `src/telemetry.ts`
- **职责**: 本地可选遥测 —— 将事件以换行分隔 JSON 追加到 `.claude/telemetry/events.jsonl`,默认关闭,绝不上传网络。
- **主要导出**: `Telemetry` 类 (`record`)、`resolveTelemetryOptions(workspaceRoot)`
- **依赖**: fs、path

### 11. 辅助工具模块

#### `src/types.ts`
- **职责**: 全局类型定义中心 —— Message/ContentBlock/ToolCall、Tool 系统接口、流式事件、Loop 事件、ModelConfig、权限类型等。
- **主要导出**: (均为类型) `Message`、`UserMessage`、`AssistantMessage`、`ToolResultMessage`、`ContentBlock`、`ToolCall`、`Tool<T>`、`ToolInput`、`ToolResult`、`ToolContext`、`PermissionMode`、`PermissionResult`、`ModelConfig`、`ModelCaller`、`StreamEvent`、`LoopEvent`、`LoopOptions` 等
- **依赖**: 无 (纯类型模块)

#### `src/hooks.ts`
- **职责**: PreToolUse/PostToolUse 拦截机制 —— 让调用方在权限检查前观察/阻止/改写工具调用,或在执行后替换给模型的结果,按工具名或 `*` 匹配。
- **主要导出**: `HookRegistry` 类;接口 `Hook`、`PreToolUsePayload/Outcome`、`PostToolUsePayload/Outcome`
- **依赖**: types (ToolResult)

#### `src/effort.ts`
- **职责**: 推理努力等级 (/effort) —— low→medium→high→xhigh→max + ultracode 档位,映射到 provider adapter 的 reasoning_effort,并提供 CLI 可视化选择器渲染。
- **主要导出**: `getEffort`、`modelSupportsReasoningEffort`、`openaiReasoningEffort`、`EFFORT_TIERS`、`EFFORT_DESCRIPTIONS`
- **依赖**: chalk、types

#### `src/skills.ts`
- **职责**: Skill 注册表 —— 可发现、可加载的命名 prompt+行为包,供 `/skills` 命令与 SkillTool 解析。
- **主要导出**: `registerSkill`、`getSkill`、`listSkills`、`resetSkills`;接口 `SkillInfo`、`Skill`
- **依赖**: 无外部依赖 (内置 skill 启动时 seed)

#### `src/file-refs.ts`
- **职责**: 展开用户输入中的 `@path` token —— 从磁盘读取文件内容附加为上下文,路径须在 workspace 内,逃逸/缺失/过大则报告而非注入。
- **主要导出**: `expandFileRefs`;接口 `FileRefResult`
- **依赖**: fs、path

#### `src/git-context.ts`
- **职责**: 注入 git 仓库状态快照 (分支/dirty 文件/最近提交) 到 system prompt 动态区;另提供 /commit 与 /pr 用的 diff 摘要收集与 conventional-commit 主题建议。
- **主要导出**: `gatherGitContext`、`formatGitContext`、`gatherDiffSummary`、`suggestCommitSubject`;接口 `GitContext`、`GitChangedFile`、`GitDiffSummary`
- **依赖**: child_process (execFile)、util

#### `src/change-tracker.ts`
- **职责**: 记录会话期间文件变更 (write/edit/multiEdit 上报),按 sessionId 隔离,供 /diff 汇总本次会话改了什么。
- **主要导出**: `recordChange`、`getChanges`、`clearChanges`、`resetChangeTracker`
- **依赖**: 无外部依赖 (纯内存 Map)

#### `src/markdown.ts`
- **职责**: Markdown 渲染器 —— marked lexer 解析后转 ANSI 终端彩色文本,消费粗体/斜体标记,渲染标题/列表/代码/引用,表格用 box-drawing 边框 (窄终端回退竖排)。
- **主要导出**: `renderMarkdown`、`renderTable`、`formatToken`
- **依赖**: chalk、marked、terminal-width

#### `src/terminal-width.ts`
- **职责**: 终端列宽测量与 ANSI 辅助 —— 替代 `string-width`/`strip-ansi`,正确处理 CJK 全角、emoji、组合标记。
- **主要导出**: `stripAnsi`、`visualWidth`、`graphemes` (生成器)、`padAligned`、`terminalColumns`、`terminalRows`
- **依赖**: 使用 `Intl.Segmenter` (可用时);无 npm 依赖

#### `src/lsp.ts`
- **职责**: 真正的长生命周期 LSP 连接 (M14.5) —— 经 stdio 直连 tsserver 的 JSON-RPC 线协议 (`Content-Length` 帧),按 workspace 复用单进程,同步拉取语法/语义诊断;回退时仍用 lsp-legacy 纯函数。
- **主要导出**: `LspClient` 类、`getLspClient`、`disposeAllLspClients`、`clearLspClientCache`;re-export `parseTscOutput`/`filterByFile`/`formatDiagnostics`
- **依赖**: child_process (spawn)、path、fs、module (createRequire)、lsp-legacy、typescript

#### `src/lsp-legacy.ts`
- **职责**: 旧版 LSP 纯辅助函数 (保留给 tsc 回退路径与测试) —— 解析 `tsc --noEmit` 非格式化输出为诊断、按文件过滤、格式化为模型友好报告。
- **主要导出**: `parseTscOutput`、`filterByFile`、`formatDiagnostics`;接口 `Diagnostic`
- **依赖**: 无 (纯正则解析)

---

### 12. TUI 终端界面

> TUI 模块位于 `src/tui/` 子目录,基于 Ink (React) 实现。

#### `src/tui/banner.ts`
- **职责**: TUI 启动横幅 —— 在 Ink 接管前一次性打印到 stdout,Claude 吉祥物 + 欢迎面板 (左栏欢迎语/吉祥物/模型/cwd,右栏 Tips/What's new)。
- **主要导出**: `renderBannerLines(info)`、`printBanner(info, out?)`;接口 `BannerInfo`
- **依赖**: os、chalk、terminal-width

#### `src/tui/effort-fx.ts`
- **职责**: `/effort` 滑块的帧构建器 —— 纯函数渲染单帧 ANSI 字符串数组,max 档彩虹流、ultracode 档动态紫色像素场 (涟漪 + 故障抖动 + 辉光)。
- **主要导出**: `buildEffortFrame(opts)`、`ORDER` (EffortLevel 排序)
- **依赖**: chalk、effort

#### `src/tui/store.ts`
- **职责**: TUI 可观察状态容器 —— 桥接命令式 agent loop 与声明式 React/Ink,纯 pub/sub 便于单测。
- **主要导出**: `TuiStore` 类 (实现 `useSyncExternalStore` 契约;mutator 包括 `addUserMessage`/`appendStreaming`/`commitStreaming`/`startTool`/`finishTool`/`addUsage`/`setBusy`/`setSpinner`;overlay 异步方法 `askPermission`/`askQuestion`/`askEffort`)
- **依赖**: types、effort;无 React 依赖
