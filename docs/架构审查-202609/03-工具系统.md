## 1. 工具注册机制

### 1.1 Tool 接口（`src/types.ts:337-422`）

接口设计相当完整，核心字段分四类：

| 类别 | 字段 | 说明 |
|---|---|---|
| 描述 | `name` / `description` / `promptDescription` / `inputSchema` | `promptDescription` 是给 LLM 的版本（含参数散文说明），`inputSchema` 是手写 JSON Schema 形状 |
| 能力声明 | `isReadOnly(input?)` / `isConcurrencySafe(input?)` / `isDestructive?(input)` / `requiresApproval?()` | **数据驱动**（M29）：可传谓词，如 Bash 对 `cat` 只读、对 `rm` 不是 |
| 执行 | `validateInput?` / `call(input, context)` / `checkPermissions` / `formatResult` | 双层权限：工具自查 + 系统级 |
| 治理 | `interruptBehavior` / `timeoutMs` / `maxResultSizeChars` / `getPath?` / `aliases?` / `searchHint?` | 见 §5——其中 4 个是**死元数据** |

`ToolContext`（`types.ts:174-253`）承载：workspaceRoot/allowedDirectories、permissionMode（含运行时 getter/setter 供 Shift+Tab）、modelConfig、askUser/askUserQuestion、permissionClassifier、hooks、abortSignal、fork 支持（getParentMessages/parentSystemPrompt/subagentDepth）、collapseStore（F2 上下文恢复）。

### 1.2 双代构建器与 fail-closed 默认（`src/tools/registry.ts`）

- **`createTool`**（208-210）：legacy 路径，手写 JSON Schema、无运行时校验。
- **`buildTool`**（232-265）：规范路径。`z.strictObject` → `zodToJsonSchema`（openApi3、无 $ref，WeakMap 按 schema 身份缓存，214）；安装 `validateInput` 严格解析，失败抛 `InputValidationError`（66-74），executor 将其转为模型可自纠的 `<tool_use_error>` 信封（81-83；`agent-loop.ts:782`）。**全部 40+ 工具均已迁移到 buildTool**，createTool 实际无使用者。
- **fail-closed 默认**（`TOOL_DEFAULTS`，92-99 + `finalizeTool`，151-197）：未声明 → 非只读（走审批）、非并发安全（串行）、`interruptBehavior:"kill"`、`maxResultSizeChars:30_000`；`requiresApproval` 默认 `!isReadOnly`，`isDestructive` 同理。这是设计上的亮点——"忘记声明落在最安全状态"。

### 1.3 注册表组织

`ToolRegistry`（13-55）= `Map<name, Tool>` + 注册顺序的 `sources` 数组（供 `/tools` 列出 core/mcp 来源），重名注册直接 throw。

装配在 `src/cli-tools.ts:37-162`：
1. `CORE_TOOLS`（`core-tools.ts:47-93`，47 项，含 DesignSync 禁用桩）逐个 register；
2. 磁盘 skills/commands/agents 加载（`.claude/skills|commands|agents` + 插件目录）；
3. MCP：项目级配置本应交互式 trust 确认（110-125，⚠️ 该信任门因路径不匹配失效，见分册 04 §5.4）；MCP 工具以 `mcp__server__tool` 命名、手工对象字面量构建（`mcp/index.ts:490-560`，`isReadOnly:()=>false` 保守、首次调用需审批）；
4. MCP resource 工具 + `tool_search` 工厂**最后**注册（能看到全集）；
5. `onToolsChanged` 热重载：先快照 incoming 再 unregister/register，保持 live 数组身份（148-162）——细节考究。

### 1.4 暴露给 LLM

- **API tools 参数**：`formatToolsForAnthropic`（`anthropic-adapter.ts:224-239`）映射 `name/promptDescription/inputSchema`，并在最后一个工具打 `cache_control` 缓存整个 tools 前缀；OpenAI 路径 `formatToolsForOpenAI`（`llm-adapter.ts:299-308`）。
- **系统提示**：`buildToolDescriptionsSection`（`system-prompt.ts:98-109`）又把每个工具的**完整 promptDescription** 逐条 dump 进 "AVAILABLE TOOLS" 段。⚠️ 与 tools 参数完全重复（注释声称"只放 name+intent 避免双倍 token"，实际放的是全文）——约 50 个工具 × 100-200 token × 2 份。
- **执行链**：`agent-loop` STEP5 → `executeToolCalls`（`tool-executor.ts:409-521`）按 `isConcurrencySafe` 贪心分批（86-98，保序：`[read,write,read]` 不重排），safe 批并行（上限 `maxToolConcurrency`，默认 10），与 abort 单 Promise race → `executeSingleTool`（162-400）：JSON.parse → validateInput → PreToolUse hook（可改写 input，改写后**重新过 schema**，240-259）→ `tool.checkPermissions` → 系统级 `checkPermission`（`permissions.ts:421+`：deny 规则 → 阻断路径安全底线 → 只读快速放行 → plan 模式拦截 → **bypass 免疫**的危险模式 + LLM 分类器 → askUser）→ 推测缓存 → watchdog（默认 5min、上限 30min，110-156）→ `tool.call` → PostToolUse hook → formatResult → 审计日志（每个 mutating 调用全模式记录，275-309）。
- **流式提前执行**：`StreamingToolExecutor`（`streaming-tool-executor.ts`）在模型还在流式输出时，对"只读且并发安全"的 tool_use 提前起跑，STEP5 用 `take(id)` 收割——纯延迟隐藏（⚠️ 但有顺序语义竞态，见分册 01 H3）。

**小结**：注册机制是这个项目最强的部分之一——fail-closed 默认、Zod 严格校验、双层权限 + bypass 免疫安全底线、审计、hook 改写再校验，均达到甚至超过真实 Claude Code 的可观测行为。

## 2. 核心工具实现质量

### 2.1 Bash（`core/bash.ts`，454 行）——质量高

- **进程树击杀**：明确弃用 `exec`，自 spawn shell + `taskkill /PID /T /F`（Win）/ `process.kill(-pid)`（Unix，detached 进程组）（338-366），注释解释了 Windows 孙进程持管道导致的死锁（153-165）——这是真实踩坑后的修复。
- **超时**：input.timeout ≤0 时钳到 120s 防"无限挂起"（78）；超时用显式 `timedOut` 标志而非 exitCode 判断（Windows taskkill 后 exit code=1 不可区分，252-256）；**abort 优先于 timeout**（232-238）。⚠️ 但外层 watchdog 默认 5min 会先于 `timeout>300000` 的请求杀掉（见 §5.6）。
- **输出治理**：`StringDecoder` 增量解码防多字节字符撕裂（174-175，226-227 flush 尾部）；10MB 累计守卫，超限杀树并置 `truncated`（41，177-185）。
- **沙箱集成**：`sandbox-policy.ts`（`.claude/sandbox.json`）→ `sandboxViolation` 前置拒绝（84-85）；`native:true` 时走 `runWindowsSandbox`（PowerShell 宿主 + 输出重定向捕获，OEM/GBK 解码兜底），且做了 **cmd 引号奇偶校验**防止重定向路径落入引号区吞掉 stdout（105-113，`cmdQuoteToggles` 318-330）；后台执行在 native sandbox 下明确拒绝（87-94）。
- **后台任务**（379-454）：`createJob` 注册会话桶，**故意忽略 abortSignal**（后台任务语义要活过本轮，注释 371-377）；TTL 默认 2h、钳 24h；`settleJob` 幂等（error+close 双事件）；完成后经 `notifications.ts` 推 `<task_notification>`，模型无需轮询（M41）。
- **会话 cwd**（`session-cwd.ts`）：仅记忆**裸 `cd <dir>`**（`parseCdTarget` 拒绝复合命令，50-67），目录消失自动清 stale（23-33）。
- **数据驱动只读**（`utils/command.ts:158-294`）：保守 allowlist；拒绝 `$()`/反引号/进程替换/`tee`/换行/未引号的 shell 活性字符；`git` 只放行 11 个只读子命令 + safeFlags 白名单；通配符经 `wildcardCouldReachSecretPath`（108-127）检查（`cat .e*` → 需审批）；`$VAR` 除 HOME/USERPROFILE 外一律不可信。PowerShell 版本（308-376）更保守且修复过 `;\b` 边界漏洞（注释 318-322）。

### 2.2 Edit / MultiEdit（`core/edit.ts`）——质量高

- **精确替换**：唯一性计数（99-109，含空串死循环守卫 `|| 1`）；0 匹配 → 提示重读；N 匹配且非 replace_all → 要求加上下文（111-127）。
- **替换安全**：index splice 而非 `String.replace`，避免 `$&/$1` 特殊模式污染（129-141；`utils/diff.ts:spliceAll`）。
- **CRLF 容错**（`diff.ts:131-148`）：Read 剥 `\r` → 模型送 LF-only → CRLF 文件精确匹配必失败，故 miss 时升转 CRLF 对重试，且只改写匹配区（混合换行文件不误伤）。
- **失败处理**：read-before-edit 门（mtime 校验，`read-tracker.ts`）；no-op 拒绝（92-97）；ENOENT/EACCES/EBUSY 分类 + Hint（169-201）；写前 `shadowBeforeWrite` checkpoint（rewind 支持）；写后刷新 read-tracker 支持链式编辑；`recordChange` 供 change-tracker；LCS 真 diff（非集合成员判断，`diff.ts:62-74` 注释了旧实现的错误）+ 仅显示的带行号 diffLines（152-155）。
- **MultiEdit**（217-394）：内存中顺序应用、任一失败零写入、单次提交（原子）；每条 edit 对**当前工作文本**重新做 CRLF 容错（298-300）。

### 2.3 Read（`core/read.ts`）——质量好，有一个显著缺口

- 图片/PDF：5MB 门在 `readFileSync` **之前**（85-90，注释说明防 OOM）；base64 进 `images` 块，loop 以合成 user 消息注入（`agent-loop.ts:820-831`）；Anthropic 路径正确把 `application/pdf` 转为 `document` 块（`anthropic-adapter.ts:108-122`）——但 **OpenAI 路径直接塞 `image_url` data URL（`llm-adapter.ts:82-91`），PDF 必挂**。
- 大文本：>10MB 用 fd 只读前缀（99-108）；二进制检测=前 8KB null 字节；`.ipynb` 结构化渲染（cell 类型/execution_count/输出计数 + cell 内行号，143-180），解析失败降级为纯文本。
- 行号：4 空格填充 `cat -n` 风格（196-202）；CRLF 剥 `\r`（190-194，注释解释防止模型把 `\r` 带进 Edit）；offset/limit 默认 2000 行。
- `maxResultSizeChars: Infinity`（41）防 "Read→spill→Read" 死循环。
- ⚠️ **缺口**：没有**单行字符截断**（真实 CC 每行截 2000 字符）。一个 minified 单行 10MB 的 JS：limit 按行计=1 行、Infinity 又豁免 adapter 截断 → 10MB 原文直进上下文。

### 2.4 Grep（`core/grep.ts`，544 行）——最重的核心工具，工程质量高

- **打包 ripgrep**（`@vscode/ripgrep`，lazy import + memoize，28-33），`execFile` 直传 argv、无 shell 层（239-250 注释说明旧版 Unix 引号在 cmd.exe 下已坏、静默 fallback 的历史）；`--` 终止选项解析防 `-` 开头 pattern 被当 flag（277-279）。
- **安全**：候选文件先 `rg --files` 枚举，再**逐文件** `resolveInWorkspace` + `isBlockedPath` 双查（318-327，注释明确"ignore globs 不是安全边界"）；共享 listing promise **不捕获调用方 abortSignal**，各调用者 `raceAbort` 自己的信号（288-316）——避免了"一人 abort 全员误报"的共享缓存经典 bug。
- 32 文件/批（Windows argv 长度限制），单批 30s + 10MB maxBuffer，跨批 10MB sizeCapped 时如实置 `truncated`（356-360）；rg exit 1+空 stdout = 无匹配（165-167）。
- **Node fallback**（376-544）：fast-glob + `vm.Script` 在 100ms 可中断 deadline 下跑 regex（JS 定时器无法打断回溯，415-437 注释到位）；总 5s deadline；每文件 setImmediate 让出事件循环；PCRE2 请求明确报"不可用"。⚠️ 小毛病：content 模式对行做 `.trim()`（504），丢缩进、与 rg 路径输出不一致；`files_with_matches` 模式下 `results` 恒空导致 headLimit break 失效（只能靠 5s deadline 兜底）；无 `offset` 参数；head_limit 把上下文行计入行数。

### 2.5 Glob / Write / PowerShell

- **Glob**（102 行）：`path` 参数过 containment、pattern 拒绝绝对路径与 `..` 段（53-58）；fast-glob 忽略 node_modules/.git、`dot:false`、`onlyFiles`；TTL 缓存（M3，写路径统一 `invalidateToolWritableScopes`）；⚠️ **字典序排序取前 500**（73-78）——真实 CC 按 **mtime 降序**取 100（"最近改的最相关"），语义偏差。
- **Write**：10MB 内容上限；已存在文件强制 read-before-write（75-81）；自动 mkdir 父目录；checkpoint + recordChange + codePreview（仅 UI）。
- **PowerShell**（278 行）：与 Bash 同契约；native sandbox 下把脚本落盘为带 BOM 的临时 `.ps1` 用 `-File` 执行（89-106，注释解释 cmd→argv→脚本三层解析器引号不一致的实战 bug；BOM 防 PS5.1 按 ANSI/GBK 读非 ASCII）；非 native 路径注入 `[Console]::OutputEncoding=UTF8` 前缀防 CJK mojibake（142-147）。⚠️ 无 `run_in_background`（与 Bash 不对称）。

## 3. 扩展工具

### 3.1 Task / Agent —— subagent 派生（两套并存）

共同骨架：模块级 `Semaphore`（默认 3，env 可调）→ fork 判定（省略类型名 + 父环提供 `getParentMessages`/`parentSystemPrompt`）→ fork 继承父历史**且逐字复用父 system prompt**（共享 prompt cache）→ `agentLoop` 子环 → 消费事件（tool_use/tool_results 转发 `onSubAgentProgress`）→ **只返回最后一条 assistant 文本**（`extractLastAssistantText`，`subagents.ts:204-213`，注释解释了旧版累积 narration 泄漏的错误）；继承历史用 **identity Set** 标记而非长度索引（autoCompact 原地 splice 会漂移，`task.ts:157-160`）→ `max_turns` 时 `collectPartialReport` 做一次有界、禁工具的 handoff 调用，结果永远标注 incomplete（`subagent-report.ts`）。

安全：`createSubAgentApprover`（`utils/subagent-security.ts`）——capability-based，只有"工具自报只读 + 无 riskHint + 不要求审批"才自动放行，否则转发父 approver，无父 approver 时 restrictive 拒绝；父 abortSignal 经 `CancellationScope` 级联（`task.ts:176`）。

差异（=漂移）：

| | Task（`extended/task.ts`） | Agent（`extended/agent.ts`） |
|---|---|---|
| fork 深度上限 | 1（:42） | 2（:41） |
| 默认 maxTurns | 10 | 20 |
| 子环 sessionId | **共享父 id**（read-tracker 互通） | `父id-agent-${Date.now()}`（隔离，但同毫秒并发会撞桶） |
| approver | restrictive=true | 默认 restrictive |
| 附加能力 | — | model/effort 覆盖、`isolation:"worktree"`、`run_in_background`（job 化 + self-settling kill，201-246）、嵌套 agent `tryAcquire` 防"子等父、父等子"死锁（272-286）、SubagentStop hook |

Typed subagent 注册表在 `subagents.ts`（code-explorer / code-reviewer / general + 磁盘 `.claude/agents/*.md`），`resolveSubagentTools` 支持 `mcp__*` 通配（138-153）。⚠️ code-explorer 号称 read-only 却带 `bash`（:76），靠数据驱动只读判定兜底。

Team 工具（`breadth/team.ts`）是第三条派生路径：常驻命名 agent + `send_message`（可 background fire-and-forget，⚠️ **无并发上限**）。

### 3.2 Workflow 编排引擎（`extended/workflow.ts` + `src/workflow.ts`）

脚本模型：模型写一段 async JS body，在 **worker_threads Worker 内的 `vm.createContext`** 中执行（`WORKFLOW_WORKER_SOURCE`，289-345）；沙箱注入 `agent(prompt,{label})` / `parallel(thunks)` / `pipeline(items,...stages)` / `log` / `phase` / `args`；`agent()` 经 postMessage 桥回主线程跑 `runWorkerAgent`（工具过滤为 read/glob/grep/bash，:84），promise 以 id 配对回填。治理：`vm.runInContext` timeout（`Math.min(timeoutMs,10s)`）只约束**同步段**；整体默认 120s，超时 `revoked` + CancellationScope 硬取消，in-flight agent 调用拒绝（185-199）；独立 4 槽 worker 信号量（20-75，手写 acquire/release，含 abort 摘队）。⚠️ `vm` 不是安全边界（`this.constructor.constructor('return process')()` 可逃逸到 worker realm，而 worker 本身有完整 Node 权限）——实际防线是 `isReadOnly:false` → 审批门。

### 3.3 Jobs（`extended/jobs.ts` + `job-store.ts`）

会话分桶 Map、`job-N` 单调 id（/clear 后计数器保留防 id 复用撞运行中任务，155-158）；`settled` Promise 让 `job_output {wait:true}` 免轮询（race 超时定时器、败者 clear，82-97）；每会话 50 上限**只驱逐已 settle** 的（running 永不丢，防进程树泄漏，103-112）；`settleJob` 幂等 + 推 500 字符尾巴的通知。

### 3.4 Cron / Scheduler / Wakeup —— 持久化调度

- **引擎**（`extended/cron-shared.ts`）：`validateCron` 支持 5 字段（star/list/range/step）+ `+N` 相对秒；`cronMatches` 实现标准 **DOM/DOW "双限定则 OR"** 语义（156）、0/7 双 Sunday；`collectDueCronJobs` 做**分钟级去重**（`lastFiredMinute`，217）、one-shot 触发即删；上限 50。
- **持久化**：`durable:true` → `<root>/.claude/scheduled_tasks.json`；加载时逐条校验（坏 cron 跳过不中断）、保留 id 使 CronDelete 跨重启有效（270-309）；scheduler 每次触发 pass 后**重写文件**，防已消费的 one-shot 重启复活（`scheduler.ts:98-102`）。写失败静默（"durability 是便利不是保证"）。
- **触发循环**（`scheduler.ts`）：1s `setInterval`（unref，不吊住进程退出）；**只在 REPL idle 时投递**，busy 时进 parked 队列，busy→idle 翻转时 FIFO 补投（104-114）；同时把 unseen 后台完成通知浮到 UI（peek-only，模型仍会收到队列副本）。
- **ScheduleWakeup**（/loop 动态模式）：`hrtime.bigint` fireAt、60-3600s 钳制、promptDescription 内嵌 **prompt cache TTL 经济学**（<300s 保温 / >1200s 摊薄 miss / 恰好 300s 最差，119-129）——这段提示词工程相当讲究。
- ⚠️ 与真实调度器相比缺：recurring **7 天自动过期**、非整点分钟的**抖动**建议只有文字没有强制。

### 3.5 Web 工具的 SSRF 防护——本项目最扎实的安全模块

- **`utils/public-http.ts`**：先 `dns.lookup(all)` 解析，**每一个** A/AAAA 应答都过 `isPrivateNetwork`，然后**直连已校验的 IP**（hostname 字段填 address，SNI/Host 保留原名，52-54）——同时防 DNS rebinding 与代理侧二次解析；仅接受 `identity` 编码（拒压缩 body 绕过 size cap）；3xx 只取 header、`destroy()` 不下载不可信重定向体；流式 size cap 超限 destroy；`close` 且未 `readableEnded` → 显式 reject 防半死 socket 挂起（105-109）。
- **`InputValidator.isPrivateNetwork`**（`utils/input-validator.ts:193-291`）：覆盖 IPv6 方括号形态、**IPv4-mapped IPv6 两种拼写**（`::ffff:127.0.0.1` 与归一化 `::ffff:7f00:1` 的 hex 解码，275-291）、0.0.0.0/::、CGNAT 100.64/10（含 Tailscale）、link-local、ULA、TEST-NET、benchmarking、multicast——注释明说旧 regex 版本漏了哪三类。
- **web_fetch**：**手动跟随重定向、每一跳重新 validateUrl**（≤5 跳，275-306），注释点破 `redirect:"follow"` 只见最终 URL 的 `public→169.254.169.254→public` 链攻击；15s 定时器**贯穿 body 读取**（防 slow-drip，125-145）；S6 用 fast model 对页面做 `fetchInfo` 定向抽取（20k 输入、独立 15s），失败优雅降级为原文 + 截断。
- **web_search**：无 key 方案（DDG lite → DDG html → Bing），regex 刮 HTML（三个 parser 都导出供测试）；进程级 latch 防每次白付 15s 超时；2MB body cap。⚠️ 刮 HTML 本质脆弱；`freshness`/Bing 组合下 df 参数被丢弃；无 `allowed_domains/blocked_domains` 结构化参数（用 `site:` 拼接替代）。

### 3.6 其余扩展工具速评

- **repl**：持久 node/python 解释器进程，marker + JSON 行协议，**按 seq 匹配响应**（注释记录了旧 FIFO shift 在一次超时后整个会话错位的 bug，156-166）；EPIPE 吞掉、进程退出 reject 全部 pending 且防 stale exit 误删新会话（175-184）；node 侧用持久 vm context 保 `let/const` 状态。
- **memory-save**：`MemoryStore` jsonl 追加 + 去重；`agent_type` 时同步写 `agent-memory/<type>/MEMORY.md`（该类型 subagent 的 system prompt 每次注入）。
- **restore-context**：从 `collapseStore` 按 `tool_call_id` 找回被 context-pipeline 驱逐的原文，50k/次 + offset 续读——对 prompt-cache 友好（不重写历史）。（⚠️ store 生命周期问题见分册 01 M8。）
- **report-findings / structured-task-tools / todo**：薄封装 + 会话注册表，无特殊问题。
- **design-sync**：完整 Zod discriminatedUnion 契约但 `isEnabled:()=>false` 的诚实桩（"无认证后端"），使旧会话回放得到明确失败而非未知工具。
- **breadth/interactive**：EnterPlanMode/ExitPlanMode 运行时翻转 `context.permissionMode`（同一 ToolContext 对象跨调用复用所以生效）；ExitPlanMode 走 `requestPlanApproval` 审批面板、支持用户在编辑器里改计划后回传（84-115）；AskUserQuestion 无回调时优雅降级为文本列表。

## 4. 输出治理

- **truncation（`tools/truncation.ts`）**：P0-1 架构——**历史与会话快照永远存全文**，截断发生在 **API 调用时**（两个 adapter 的 tool 消息转换处调 `truncateToolResult`，按 `getToolMaxChars(toolName)` 尊重每工具 `maxResultSizeChars`；Read=Infinity 豁免）。preview = head 12k + 尾 4k + 省略标记，且 head/tail 各再受预算 60%/20% 钳制，保证 preview 恒短于预算（62-68）。`spillIfLarge`（写 `.ccr/tool-results/`，dot 前缀被 Glob/rg 天然忽略）保留为兼容路径，写盘失败降级内存截断、**永不抛**。
- **summary（`tools/summary.ts`）**：M36"用模型流式窗口隐藏延迟"——工具批完成后，若总输出 ≥2000B，用 fast model 把每工具 600 字符 snippet 压成 1-3 行 digest，以 `<system-reminder>`（明确声明"是摘要不是替代"）在**下一轮边界非阻塞消费**；模块纯函数 + 注入 summarizer，reject/超时一律吞掉返回 null——"延迟隐藏绝不能添加延迟"。
- **UI/模型分轨**：`metadata.summary`（"12 matches"）、`codePreview`、`diffLines`、`todos` 均声明为 display-only，模型只见 `content`——`types.ts:147-171` 的契约注释清晰。
- ⚠️ 反效果一处：`defaultFormatResult`（`registry.ts:136-143`）对所有带 metadata 的成功结果追加 `\n[Xms]` 时间戳后缀，而 executor 恒注入 durationMs（`tool-executor.ts:378-381`）→ **每个成功结果末尾都多一行 "[15ms]" 噪音**进模型上下文。

## 5. 弱点

### 5.1 【最重要】失败命令的输出被 formatResult 丢弃

`defaultFormatResult` 在 `result.error` 存在时**只返回 error、丢弃 content**（`registry.ts:136-139`），而 Bash/PowerShell 的非零退出路径把 stdout/stderr 放在 `content`、错误说明放在 `error`（`bash.ts:271-286`；`powershell.ts:258-270`；native sandbox 分支 `bash.ts:139-148` 同）。`agent-loop.ts:782` 只把 `formatted` 写进模型历史。结果：**模型对 `npm test` 失败只看到 `Error: Command failed (exit code: 1)\nHint: check the command syntax and arguments`，看不到任何测试输出**（唯 timeout 路径在 error 里塞了前 500 字符，`bash.ts:265`）。已用脚本静态复现确认该行为。这是与真实 CC 差距最大的一处（真实 CC 会把输出与错误一起回传），且项目 148 个测试文件中无一断言此路径。同类问题：`error`+`content` 双设的 Edit/Write 分支 content 为空所以无碍，但任何未来工具"error+部分成果"都会被吞。

### 5.2 死元数据 / 未兑现的接口

- **`aliases` 从未被解析**：dispatch 只按 `t.name` 精确匹配（`tool-executor.ts:69,172`），全仓库无别名解析代码。12+ 个工具声明了 aliases（如 `job_output` 的 `TaskOutput`、`CronCreate` 的 `schedule_cron`）——模型若真用别名调用会得到 "Unknown tool"。更糟的是 aliases 里埋着**未爆的冲突**：`job_kill` alias `task_stop`（`jobs.ts:133`）与 team 工具真名 `task_stop`（`team.ts:221`）撞车；`CronCreate` alias `schedule_cron` 与真工具 `schedule_cron`（`orchestration.ts:311`）撞车——一旦实现别名解析立即二义。
- **`searchHint` 不参与 tool_search 打分**（haystack 只有 name+description+promptDescription，`breadth/index.ts:358`）。
- **`interruptBehavior` / `getPath` 无任何消费者**（仅 registry 声明与一个测试断言）。

### 5.3 工具间重复代码

1. **bash.ts ↔ powershell.ts**：spawn/killTree/StringDecoder/timer/abort/exit 归约约 130 行近乎逐行重复（`powershell.ts:152-277` vs `bash.ts:167-297`），native sandbox 结果三分支（abort>timeout>refusal）也重复（`powershell.ts:111-136` vs `bash.ts:122-148`）。
2. **task.ts ↔ agent.ts**：~70% 重复（fork 判定、loop 消费、identity Set、partial report、输出提取），且已发生行为漂移（fork 深度 1 vs 2、maxTurns 10 vs 20、sessionId 共享 vs 加后缀——后者导致 **Agent 子代理的 Read 不满足父会话的 read-before-edit 门，Task 的却满足**，同名语义不同行为）。
3. **三套调度入口**：`schedule_cron`+`sleep`（orchestration）与 `CronCreate/Delete/List`（cron-tools）功能重叠、同时注册；再加 `ScheduleWakeup`，共 6 个调度类工具。
4. **两套任务清单**：`todo`（全量替换式）与 `TaskCreate/Get/Update/List`（结构化+依赖图），加上 team 的 `task_list` 与 `job_list`，模型面对 4 个"列表"面。
5. Edit/MultiEdit 的 errno 映射块逐字重复（`edit.ts:169-201` vs `355-384`）。

### 5.4 命名/接口不一致

- 工具名混用 snake_case（read/edit/bash/job_list）与 PascalCase（Agent/TaskCreate/CronCreate/MemorySave）；真实 CC 统一 PascalCase（Read/Edit/Bash/TodoWrite）。
- 参数风格混杂：`filePath`（camel，且真实 CC 用 `file_path`）、`job_id`/`timeout_ms`（snake）、`old_string`/`replace_all`（snake，随官方）、`delaySeconds`/`fetchInfo`（camel）、Grep 直接暴露 `-A/-B/-C/-i/-n/-o` CLI flag 名。
- Task 用 `subagent_name`、Agent 用 `subagent_type`（官方是后者）；web_fetch 用 `fetchInfo`（官方 `prompt`）。
- **Windows 上 Bash 实际跑 cmd.exe**（`bash.ts:306-308` 取 ComSpec），但 promptDescription 未告知模型 shell 方言——真实 CC 的 Bash 描述明确写 "runs Git Bash (POSIX sh), not cmd.exe"。模型按 POSIX 写 `&&`/引号/`$(...)` 会在 cmd 下以各种方式失败，而 read-only allowlist 却按 POSIX 命令表（cat/ls/grep）构建。
- `tool_use_error` 双重包装：executor 包 `<tool_use_error>`，defaultFormatResult 又加 "Error: " 前缀。

### 5.5 与真实 Claude Code 的功能差距

已有：NotebookEdit ✓、Skill ✓（含 `context:'fork'` 子代理运行）、AskUserQuestion ✓、Enter/ExitPlanMode ✓（含计划审批+编辑回传）、Enter/ExitWorktree ✓、BashOutput/KillShell 等价物 ✓（job_output/job_kill）、Cron 三件套 ✓、ScheduleWakeup ✓、ReportFindings ✓、ToolSearch ✓、Team/SendMessage ✓、Task 结构化四件套 ✓、MultiEdit ✓、DesignSync（诚实桩）。
缺失/偏差：
- **SlashCommand 工具**（模型直接调 slash command）无对应物（skills 部分覆盖）；
- Read 无 PDF `pages` 参数、无单行 2000 字符截断、无 25k 行上限；
- Glob 不按 mtime 排序（语义差异见 §2.5）；Grep 无 `offset`、无 `multiline-dotall` 显式开关；
- Bash 无 `dangerouslyDisableSandbox` 参数（沙箱走 policy 文件，模型无逃生阀）；
- web_fetch 无 15 分钟响应缓存；web_search 无 allowed/blocked_domains；
- OpenAI 兼容路径 PDF 支持断裂（§2.3）。

### 5.6 并发问题

- **无全局 subagent 并发上限**：Task(3)、Agent(3)、workflow worker(4)、team background（**无上限**，`team.ts:135-139` fire-and-forget）各自为政，混合 fan-out 理论可达 10+ 并发模型环 + 任意 team 环；且信号量全部**模块级全局**，多会话（TUI 多开/测试）互相挤占。
- Agent background 的 sessionId 后缀 `Date.now()`（`agent.ts:356`）：同毫秒并发两个 background Agent → read-tracker/job/notifications 桶串号。
- job-store 仅在 >50 时驱逐 settled，running 无上限（`job-store.ts:105-112`）——理论上 51 个并行后台进程树。
- Bash 后台溢出判断用 `job.stdout.length`（UTF-16 code units）而前台用 `Buffer.byteLength`（`bash.ts:399` vs `178`），同一 10MB 阈值两种度量。
- watchdog（默认 5min）与 Bash `timeout` 参数互不知情：模型请求 `timeout:600000` 会在 5min 被 `ToolWatchdogTimeoutError` 掐断（Bash 未设 `tool.timeoutMs`，`tool-executor.ts:110-117,349-353`），错误信息与"命令超时"混淆。

### 5.7 安全边界备注（非漏洞，但应文档化）

- workflow 的 vm 沙箱可被原型链逃逸（威胁模型=模型写的脚本经审批门执行，与 Bash 同级，但 promptDescription 未如实说明）；worker 描述"read-only"与授予 bash 矛盾（`workflow.ts:84` vs `extended/workflow.ts:31-33`）。
- `WEB_SEARCH_ENDPOINT` env 可把搜索指向内网（用户自配，可接受）。
- 正面：`resolveInWorkspace` 的三重防护（前缀别名 `/proj` vs `/proj-evil`、绝对路径覆盖、symlink 逃逸+环检测，`utils/path.ts:39-141`）与 `BLOCKED_PATTERNS` bypass 免疫底线（`permissions.ts:208-250`）质量很高。

## 总评

这套工具系统在**安全工程**（fail-closed 默认、SSRF 纵深、路径三重防护、bypass 免疫底线、保守只读分类器）和**Windows 实战细节**（进程树击杀、cmd 引号奇偶、GBK/BOM、taskkill 退出码语义）上明显投入了真实踩坑成本，注释里大量"旧实现的 bug 是什么、为什么这样修"的记录，成熟度高于一般复刻项目。主要短板集中在三处：**①错误路径的信息保真**（失败命令输出被 formatResult 吞掉是最高优先级缺陷）；**②重复演化的双胞胎工具**（Task/Agent、bash/powershell、两套 cron、两套 todo）带来的行为漂移与模型困惑；**③声明了但未兑现的接口面**（aliases/searchHint/interruptBehavior/getPath 四项死元数据）。约 50 个工具全量暴露 + 系统提示重复描述，也使 token 开销和工具选择歧义高于真实 Claude Code。
