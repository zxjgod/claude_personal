# 恢复未确认的 workflow 步骤

> 2026-11-14 · fix / test · Workflow、跨进程恢复

真实子进程里的第一步完成保存，第二步向文件追加一行后被强停，未返回报告。旧实现从第一个报告恢复，随后再次执行第二步。第二步的附加操作可重复发生。

新快照在每次派发前记录未确认的步骤位置。已完成报告与未确认状态在同一次原子替换中更新。`/workflows` 能在原工作区和会话中显示未确认的运行 ID。恢复入口会先检查整份记录，改参数也不会跳过检查。核对实际文件和外部影响后，可携带 `resumeFromRunId` 与 `retryUnconfirmed: true` 继续，匹配的已完成报告仍会复用。

跨进程回归确认，默认恢复和参数变更后的默认恢复都不会再写文件。显式重试只重新执行第二步。另核对了新进程能找回 `steps[1]`，其他会话无法通过列表看到该记录。失败的 worker 保留未确认状态，其部分报告不会进入完成缓存。

旧版快照仍可读取，其中只记录已完成报告。新版也无法从未确认状态判断副作用是否已经发生，或者外部 worker 是否仍在执行。重试前需要核对实际状态。历史快照保留原来记录的未确认状态。
