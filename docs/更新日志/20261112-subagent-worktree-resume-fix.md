# 恢复隔离子代理的原工作树

> 2026-11-12 · fix / test · Agent、Task、运行记录、Git 工作树

暂停草稿的 `requiresApproval` 误用了函数，导致夹具工具尚未执行。改为构建器要求的布尔值后，首次写入确实留在隔离工作树，三个恢复用例随后都复现了目录错误。省略 `isolation` 的 Agent 和 Task 恢复进入主目录，显式指定 `worktree` 的 Agent 恢复新建了工作树。

运行记录现在保存原工作树路径、分支、仓库与基点。Agent 和 Task 恢复时先取得运行记录的进程内独占权，再核对 Git 登记、实际检出目录、分支与初始基点。两种入口都使用原工作树和按 agent id 派生的工作会话，并报告保留路径。移动或删除工作树、切换分支或偏离初始基点都会阻止恢复。已自动清理的空工作树也适用这一规则。旧记录缺少工作树字段时，继续采用原有恢复行为。

`npm test -- src/__tests__/subagent-worktree-resume.test.ts` 覆盖三个恢复入口及两个拒绝场景。正向用例实际写入文件、读取持久化对话并核对工作会话，主目录的用户改动得到保留。拒绝用例移动工作树或切换分支，核对两个入口均未执行工具，且持久化记录没有被覆盖。

本机类型检查通过。恢复、委派并发、委派终态与工作树清理相关的 45 项测试通过。Windows 全量运行发现 3,262 项，其中 3,255 通过、1 跳过、6 失败。失败出现在 SDK 进程树启动和 REPL 退出期限，详情见本机 `.review-tmp/subagent-worktree-full.log`。以 `--maxWorkers=1` 单独复跑两个失败文件，17 项全部通过。

发布包构建、解包与启动验收通过，共 638 个文件。文档同步和差异检查通过。
