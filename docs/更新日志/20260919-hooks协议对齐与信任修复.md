## 二、修复

### 1. exit code 2 阻断语义（#1）

`runCommandHook` 的 stdio stderr 改为捕获（与 stdout 同样 100KB 封顶），`close` 读取退出码：**exit 2 → `{decision:"block", reason: stderr}`**（stderr 为空时回退 stdout JSON 的 `reason`，再回退各相位的默认文案）。退出码 2 优先于 stdout JSON（官方文档的阻断路径）；其他退出码忽略 stderr——`exit 0` 带日志输出不会误阻断。PreToolUse/PostToolUse/Stop 三个决策相位直接获得官方语义；生命周期事件的 `runEvent` 本就忽略命令输出，exit 2 在那里无害降级为 no-op。

### 2. 插件 hooks 信任路径（#2）

`cli.ts` 中插件 hooks 现在走与项目 hooks **相同的信任门**：交互会话复用同一个确认回调（提示带 `Plugin <name>` 标签），确认后按 `(插件目录, 配置指纹)` 持久信任；非交互保持 fail-closed 并打印明确警告（此前是静默跳过）。信任指纹仍随配置内容变化失效。

### 3. 官方 stdin 信封 + cwd + 环境变量（#3/#4）

新增 `HookRunContext { sessionId, workspaceRoot }`，经 `registerHooksFromConfig` / `loadHooksFromSettings(Trusted)` 线程化到每个 hook：

- stdin 前置官方信封字段：`session_id`、`transcript_path`（`<root>/.claude/sessions/<id>.json`）、`cwd`、`hook_event_name`（未提供 ctx 时字段省略，兼容程序化注册）；
- hook 命令 cwd = `workspaceRoot`（不再取启动目录），并导出 `CLAUDE_PROJECT_DIR` 指向同一目录。

### 4. 其余小修（#5/#6/#7）

- `parseHooksConfig`：缺省/空 `matcher` 一律按 `"*"` 处理（官方语义），不再丢弃条目。
- `hooks.ts` `runEvent`：改为 `{ ...payload, event }`，事件名不可被载荷遮蔽。
- `/hooks` 命令渲染全部四相（PreToolUse/PostToolUse/Stop/Event）。

## 三、未做（如实声明）

- PreToolUse 的 `decision:"approve"`（跳过权限提示）与 `permissionDecision: allow/deny/ask`、UserPromptSubmit/Notification 的 `additionalContext` 注入——决策面扩展属新功能，按复审建议逐步补。
- 用户级 hooks（`~/.claude/settings.json`）仍不支持；信任门按 workspaceRoot 键控，引入用户级需要单独的信任模型。
- 生命周期事件（UserPromptSubmit 等）的 exit 2 不阻断提示处理（官方行为是 stderr 展示给用户且提示不处理）——当前无害降级为 no-op。
