# 恢复被强停打断的工具批次

> 2026-11-14 · fix / test · Headless、工具结果与会话保存

真实 CLI 夹具在同一个工具批次内先修改源码，再等待 Shell 审批。旧实现已写入文件，但进程被强停后，快照仍停留在编辑前。之前的完整批次保存点只会在整个批次结算后触发。

Headless 现在在正式执行批次前保存配对的工具调用与结果占位，并在每个工具结果返回后更新快照。占位只写入恢复快照。它说明结果未知，建议恢复后检查现状再重试。正常执行的历史和 stdout 仍使用实际结果。模型流中提前启动的只读工具继续走原路径。关闭会话持久化时同样跳过这些保存。

端到端回归覆盖完整批次、下一工具等待批准，以及新快照临时文件写完但尚未替换正式文件。最后一种场景用夹具暂停真实 CLI 的重命名，再强停宿主。新进程读取上一个快照，看到结果未知以及磁盘上已经存在的编辑，随后按新要求修改并通过独立测试。同一文件内用户的原有注释均得到保留。

快照与工具对文件或外部系统的副作用各自提交。如果工具已产生副作用、结果却尚未落盘，恢复后的模型须检查实际状态。批次期间每次保存会重写会话快照，大历史和大型批次的写入开销仍待测量。

Windows `npm run test:core -- --maxWorkers=2` 通过，31 个文件、371 项，耗时 158.45 秒。类型检查、代码检查、文档同步和发布包烟测通过。发布包包含 643 个文件。
