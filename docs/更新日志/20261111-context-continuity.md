## 复现与根因

新增 `src/__tests__/context-continuity.test.ts`，首先运行四项场景，三项失败：

1. 连续 30 个并行工具批次（每批两个结果）无法压缩，输入和输出都为 91 条消息。`findSafeSplitIndex` 只接受前一条是 assistant、下一条不是 tool 的边界，因此逐批执行工具的长任务一直回退到开头。
2. 强制压缩后，任务模型看不到原始用户输入，实际文件操作无法完成指定的 `result.txt`。历史中的真实任务被摘要替换，末尾只有 synthetic 续做消息；摘要遗漏条件时没有其他保留机制。
3. 摘要调用已取消但适配器仍产生文本时，部分摘要被当成成功结果提交。摘要读取和 fast→主模型回退缺少调用者取消检查。

之后补入第五项完整 loop 取消验收，又复现：摘要期间取消后仍启动一次任务模型调用。`agentLoop` 在回合开头检查取消，但压缩是异步操作，错误捕获后会继续到下一次模型请求。

## 修复

- `src/auto-compact.ts`：若边界落在 tool 结果内，将它向前移至对应 assistant，把完整并行批次保留在尾部；相邻完整批次之间可以切分。单个不可切分大批次仍保持完整。
- 最近一条 `synthetic !== true` 的真实用户消息若会被摘要，原样保留在摘要之后、尾部之前；重复压缩只保留一次。不提升工具输出或 synthetic 通知的指令地位。
- 摘要开始、读取事件、结束和 fast 模型失败回退时检查调用者取消。取消时拒绝部分摘要，并停止回退调用。
- `src/agent-loop.ts`：异步压缩和生命周期 hook 结束后，再检查取消，避免额外任务模型请求。
- 更新原有“不再缩小即停止重试”回归，用一个真正不可分割的并行批次验证该规则；连续多个完整批次现在应允许压缩。
