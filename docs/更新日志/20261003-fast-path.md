# 2026-10-03 隐藏 fast-path 层（内部 worker / 桥接别名 / --cloud）

本轮补齐官方 CLI 在 commander 解析**之前**运行的一层隐藏分发逻辑（offset ~249994200）：
内部 worker 入口、Remote-Control 桥接别名、以及 `--cloud`/`--remote` 后端旗标。
这些是 claude 启动**自己子进程**的入口，不是用户命令——多数在缺少内部参数时直接报错、
有的会 daemonize、有的打开命名管道。用户误敲时，本 CLI 绝不能把它当作 prompt 喂给模型。

与 `--bg` 轮一致：**只实现判定层**（decision layer），全部以"点名缺口"的命名拒绝收场；
官方已有文案的逐字复刻，官方要真正干活的，文案点名本项目没有对应后端。

## 官方行为（2.1.202 win32，先二进制逆向定位，再实跑验证）

fast-path 分发顺序（全部在 commander 之前）：

1. `--claude-in-chrome-mcp` → 退出 0，静默
2. `--chrome-native-host` → 退出 0，**打开命名管道** `\\.\pipe\claude-mcp-browser-bridge-20616` 并等待
3. `--computer-use-mcp` → 退出 1，本构建直接崩栈
4. `--daemon-worker` → 读 stdin JSON；裸跑退出 2 `unknown worker kind: undefined`
5. `--bg-pty-host` → 退出 1，无输出
6. `--bg-spare` → 读 stdin 认领 spare；裸跑退出 2 `[bg-spare] missing claim sock path`
7. `--preload` → 读 stdin 等待认领（**会挂起**，实跑确认 daemonize）
8. `remote-control`/`rc`/`remote`/`sync`/`bridge` → `cli_bridge_path` → **登录门**
9. daemon / `--bg` 家族（上轮已做）

### 关键甄别：两个不同的"remote"

- `remote`（裸词，首位置参数）= **桥接别名** → 登录门，文案逐字：
  `Error: You must be logged in to use Remote Control. / Remote Control is only available with claude.ai subscriptions. ...`
  这是**账户门**，不是舰队特性门——`CLAUDE_CODE_DISABLE_AGENT_VIEW` 不改变它（实跑确认）。
- `--remote`（旗标）= **cloud 后端** → 与 `--cloud` 同路，非 TTY 拒绝，文案逐字：
  `Error: --cloud requires an interactive terminal. ...`

## 本项目实现

新模块 `src/fast-path.ts`（纯判定，不 spawn、不读 stdin、不开管道），
在 `src/cli.ts` 中**置于 bg 判定块之前**（匹配官方 fast-path 先于一切的顺序）：

- 7 个内部 worker 入口（仅按**首位置参数**匹配）→ 命名拒绝：
  说明这是内部 worker 入口、它本要做什么、本项目没有对应 worker；
  官方有裸跑文案的（`--bg-spare`、`--daemon-worker`）逐字附在括号里。
- 5 个桥接别名 → 逐字复刻官方登录门文案。
- `--cloud`/`--remote`（旗标，可在任意位置）：
  - 非 TTY → 逐字复刻官方 `--cloud requires an interactive terminal` 拒绝；
  - TTY → 点名缺口（无 cloud 后端），并注明官方同样要求 TTY 与 claude.ai 登录；
  - `--bg` 同现时**让位给 bg 解析器**（官方由 bg 路径报 "different backends" 冲突）。

`src/cli-env.ts` `--help` 增补一行，点明 `--cloud`/`--remote` 与这些内部入口均被拒绝、
绝不喂给模型。
