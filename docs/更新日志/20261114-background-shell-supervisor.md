# 宿主强停后的后台进程监护

> 2026-11-14 · fix / test · Bash、进程生命周期和跨进程恢复

真实 Windows CLI 启动三级 Node 进程树后，测试强停 CLI。原来的三个进程都继续存活，CLI 的退出清理没有机会运行。

后台 Bash 现在由独立 Node 进程启动和监护。CLI 向它发送启动或停止请求。父进程的 IPC 断开时，监护进程停止转发输出并清理命令树。Unix 使用私有进程组，Windows 从监护器持有的 shell PID 调用系统 `taskkill /T /F`。Windows 验收中，监护器需与原 CLI 分离启动才能在其强停后完成清理。发布包随附监护入口。

Windows 端到端测试确认，强停后三级进程均停止。新 CLI 恢复同一会话，`job_output` 报告任务中断，心跳文件未继续增长。独立启动的无关进程仍存活。正常退出、显式取消、TTL、SDK 清理也参加回归。

监护清理依赖操作系统和进程归属仍可追踪。主动脱离进程组或 Windows 父进程链的后代，以及监护器自身被同时强停，仍可能留下后台进程。恢复时不会用保存的 PID 发信号。快照记录中断，并保留命令实际退出状态未知这一事实。

Windows 定向进程回归 3 文件、32 项通过。最终 CLI 退出回归 5 项通过，类型、文档检查与发布包烟测通过（644 个文件）。Linux 进程组路径尚待平台实测。
