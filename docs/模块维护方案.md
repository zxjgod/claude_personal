# 模块维护方案

> 本项目（`claude_personal`）各模块的维护手册。配合 [`项目架构.md`](./项目架构.md)（定位）与 [`更新日志/`](./更新日志/README.md)（留痕）使用。
> 最后更新：2026-06-27

## 这份文档怎么用

任何「修复 bug 或更新功能」都走同一个闭环，目的是**改完后若出新 bug 能快速回溯**：

```
① 定位   读《项目架构.md》→ 用「一次请求的完整生命周期」判断改动落在哪个环节、哪个模块
         读本文档的「按症状反查模块」表，从现象直接跳到文件
② 评估   读该模块的「维护卡」——尤其「改动前必读（不变量）」与「影响半径」，
         确认会牵连哪些下游、哪些行为绝不能破坏
③ 改动   遵守不变量；动到「高风险区」要格外谨慎
④ 验证   按维护卡的「验证命令」跑针对性测试 + npm run build；按「回归清单」自查
⑤ 留痕   在 docs/更新日志/ 追加一条（见《更新日志/README.md》），
         记录：模块 / 受影响文件 / 根因 / 验证结果 / commit
```

> 核心理念：**每个改动都可追溯**。出了 bug，先查更新日志的「按模块索引」，找到该子功能历次改了什么、为什么这么改、对应哪次 commit —— 把排查从「通读代码」降为「查表」。

## 通用约定

- **ESM**：import 路径必须带 `.js` 后缀（NodeNext 解析），写 `./foo` 编译失败。
- **类型优先用可选字段**：`types.ts` 被约 90 个文件依赖，给 `Tool`/`ToolContext`/`CommandContext` 加字段一律 `optional + 默认值`，否则全仓 `tsc` 失败。
- **两条渲染栈**：TTY 走 `src/tui/`，非 TTY 走 `cli-*.ts`。改终端 UX（输入框/工具卡片/spinner/权限菜单）通常**要两边一起改**。
- **工具注册有两套来源**：`CORE_TOOLS` 数组（agent loop 用）与 `ToolRegistry`（`/tools`、ToolSearch 用），由 `cli.ts` 分别构造，需手动保持同步。
- **进程内状态**：`read-tracker`/`change-tracker`/`todo`/`team`/`worktree`/`cron` 都是进程内 Map、按 sessionId 隔离、**重启即失**。只有 sessions/.json、transcript.jsonl、memories.jsonl、telemetry 真正落盘。
- **绝不引入 `Math.random()` / `Date.now()` 到工作流脚本路径**；`tools-m9` 已用 `process.hrtime.bigint` 生成 id。

## 分层验证手册

改完后按从快到慢分层验证：

| 层级 | 命令 | 何时跑 |
|---|---|---|
| 类型门禁 | `npm run build`（= `tsc`） | **每次改动后必跑**，最先暴露大多数错误 |
| 针对性测试 | `npx vitest run <模块名>` | 改了某模块，跑它的维护卡列出的测试 |
| 全量测试 | `npx vitest run` | 跨多模块改动、或动了核心机制（agent-loop/权限/进程管理/provider） |
| 行式冒烟 | `printf '/help\nexit\n' \| node dist/cli.js` | 改了 CLI 入口/命令分发/渲染 |
| TTY 手测 | `node dist/cli.js` | 改了 TUI / 交互输入 / 权限菜单 |

**Windows 特有验证点**（本项目主力平台是 Windows，很多坑只在 Windows 复现）：
- 改 Bash：执行长命令触发 timeout + Ctrl+C 中断，确认 spinner 停、**无孤儿进程残留**（任务管理器看 `node.exe`/`cmd.exe`）。
- 改 Grep：确认 rg 缺失时回退路径工作、含空格 pattern 不出错。
- 改 PowerShell 工具：Windows 上能跑，非 Windows 上 `isEnabled()` 返回 false。
- 改路径处理（read-tracker/file-refs/permissions）：注意盘符大小写（`C:\` vs `c:\`）与正/反斜杠混用。
- 改持久化：跨进程/被杀软占用时 `renameSync` 可能抛 `EPERM`。

**无 CI 现状**：门禁全靠本地。建议改动合并前至少跑通 `npm run build` + 受影响模块的 `vitest`。

## 按症状反查模块

从「用户可见现象」直接定位到负责文件与关键函数：

| 现象 | 先看 | 关键点 |
|---|---|---|
| 斜杠命令没反应 / 未知命令 | `commands/registry.ts`、`commands.ts` | 命令是否 import 并推入 `COMMANDS`；名字是否全小写 |
| 命令打印了但没「执行」 | `commands.ts` + `cli.ts`/`tui/run.tsx` 的 prompt 分支 | prompt 注入型命令依赖 `result.prompt` 回灌 |
| 编辑被拒（说没读过） | `read-tracker.ts`、`tools.ts`(statMtimeMs) | mtime key 大小写/斜杠；`refreshRead` 是否漏调 |
| 写文件被意外拦/放行 | `permissions.ts`、`tools.ts` 三道关 | `checkDangerousPattern`/`isBlockedPath` 正则；4 模式顺序 |
| Bash 卡死 / 转圈 / Ctrl+C 无效 | `tools.ts`(BashTool)、`agent-loop.ts`(abort 竞速) | 进程树杀、`timedOut` 标志、并行 abort race |
| 429 一直重试 / 上下文超限死循环 | `agent-loop.ts`(handleModelError) | 重试预算 `MAX_*_RETRIES=3`；context_length 触发 compact |
| /cost 数字不对 / 缓存命中率怪 | `session-stats.ts`、两个 adapter 的 usage 口径 | input_tokens 是否重复计 cache |
| 会话没保存 / resume 失败 | `session-memory.ts`、`cli.ts`(save) | saveChain 串行；Windows rename EPERM；版本字段 |
| MCP 工具不弹审批 / 连不上 | `mcp.ts` | 首次确认 sticky；连接失败静默不入 Map；`npx` 找不到 |
| 流式没 token 计数 | `llm-adapter.ts` | `stream_options.include_usage`、done 延后 |
| effort 拉满没效果 | `effort.ts`、`llm-adapter.ts` | OpenAI 路径 clamp 到 high；模型名正则门控 |
| prompt 缓存每轮失效（成本飙） | `system-prompt.ts`(DYNAMIC_BOUNDARY)、`anthropic-adapter.ts` | 边界字符串被改/动态段插进稳定前缀 |
| TUI 看不到输入框 | `cli.ts`(isTTY 分流) | 任一 std 非 TTY 就落到 readline 路径（非 bug） |
| 工具卡片 ctrl+r 展开无效 | `tui/run.tsx`/`App.tsx`/`ToolCard.tsx` | `expandedId` 恒 null（已知未接上） |
| 终端对齐错乱 / 表格崩 | `terminal-width.ts`、`markdown.ts` | CJK/emoji 宽度；ANSI_PATTERN 裸 `]` 吞字 |
| git 状态/diff 不对 | `git-context.ts` | numstat 路径含空格/重命名；upstream 未设 |
| 子代理免审批跑了 bash/write | `task-tool.ts`/`team.ts`(askUser 透传) | 漏透传 `askUser` 是权限绕过 |

## 高风险区与红线

动这些区域要**格外谨慎**并强制走全量验证 + 更新日志。

### 🔴 红线（破坏即安全/正确性事故）

1. **Bash 进程管理**（`tools.ts` BashTool）：禁止回退到 `exec`/`execAsync`（Windows 孤儿进程死锁）；禁止删 `timedOut` 标志改用 `exitCode===null`；BashTool 必须保持非并发安全。历史详见 [`更新日志/`](./更新日志/README.md) 的 bash-deadlock 记录。
2. **写类工具三道关**（`tools.ts`）：`resolveInWorkspace`（沙箱逃逸）→ `isBlockedPath` → `checkDangerousPattern` 不可绕过；新增写工具必须全过。
3. **先读后改 gate**（`read-tracker.ts`）：不可改成总是 `ok:true`；`refreshRead` 不可漏调。
4. **权限分类器 fail-safe**（`permissions.ts`）：任何失败必须降级为 regex 提示而非放行；`ALLOW ≠ 跳过 askUser`。
5. **子代理 askUser 透传**（`task-tool.ts`/`team.ts`）：破坏性工具的 `askUser` 必须一路透传到子 loop，漏传 = 权限绕过。
6. **prompt 缓存契约**（`system-prompt.ts` DYNAMIC_BOUNDARY）：改边界文案/把动态内容插进稳定前缀会让缓存每轮失效（成本静默飙升）。
7. **usage 口径**（两个 adapter + `session-stats`）：缓存 token 绝不能重复计入 input。
8. **遥测隐私默认关**（`telemetry.ts`）：不可默认开启；不可把正文塞进 props。

### 🟡 已知缺口（触碰时注意，详见评审报告）

- default 模式下非黑名单 bash 是否真弹审批存疑（工具级 `checkPermissions` 可能未参与决策链）。
- `isBlockedPath` 只匹配 `input.filePath` 字符串，bash `cat .env` 不经它；正则可被 `.env`→`my.env` 误匹配。
- 危险命令黑名单易绕过（`rm --recursive`、`find -delete`、内联脚本）。
- MCP 工具默认免审批（仅首次确认）；远端可执行任意外部操作。
- `web-fetch` SSRF 可被 DNS rebinding/重定向绕过。
- `generateSimpleDiff` 算法有误（返回给模型的 diff 可能误导，不影响写盘）。
- TUI `expandedId` 工具卡片展开未接上。
- 死代码：`ToolRegistry.formatToolsForOpenAI/forLLM`、`memory-extract.extractMemoriesWithModel`（未接线）。

## 模块维护卡

> 每张卡按簇组织。`改动前必读` = 不能破坏的不变量；`验证` = 针对性命令；`影响半径` = 改它会牵连什么；`回归清单` = 提交前自查项。

### 卡 1 · 入口与 CLI 层
**文件**：`cli.ts`、`index.ts`、`cli-input.ts`、`cli-interactive.ts`、`cli-renderer.ts`、`cli-spinner.ts`、`cli-errors.ts`
**改动前必读**：① TUI 路径会提前 `return`，给 REPL 加的逻辑要在 TUI 生效须同改 `tui/run.tsx`；② `cleanup()` 是退出兜底，新增长生命周期资源必须在此释放；③ spinner 与 renderer 共用 stdout，渲染前先 `stop()+flush()`；④ `cli-interactive` 的命令列表由 cli 注入、绘制走注入的 output（勿直引 `process.stdout`）。
**验证**：`cli.ts`/`index.ts` 无专属测试 → `npm run build` + 行式冒烟 `printf '/help\nexit\n' | node dist/cli.js`；`npx vitest run cli-input cli-interactive cli-renderer cli-spinner cli-errors`。TTY 手测输入框/补全/权限菜单。
**常见故障**：Windows 管道下静默落 readline 路径（非 bug）；per-turn SIGINT handler 残留；best-effort 持久化失败刷 Warning 污染输出。
**影响半径**：`cli.ts` 回归面最大（几乎所有功能端到端过它），但无单测 → 靠 build + 手动冒烟。`cli-errors` 改文案会同时改 REPL 与 TUI 的错误提示。
**回归清单**：□ build 通过 □ 行式冒烟 □ TTY 起 TUI + `--no-tui` 回退 □ Ctrl+C 一次中断本轮、二次退出 □ 退出无孤儿进程。

### 卡 2 · Agent 循环核心 + 上下文优化
**文件**：`agent-loop.ts`、`context-snip.ts`、`speculation.ts`
**改动前必读**：① 工具结果按 `index` 回填，并发+串行两条路径必须覆盖全部 index；② `findSafeSplitIndex` 防孤儿 tool（有回归测试）；③ `LoopEvent` 形状改动牵连两套渲染 + 子代理；④ `snipContext` 幂等且只处理 string content；⑤ speculation 的 `{filePath}` 键三处强耦合。
**验证**：`npx vitest run agent-loop compaction context-snip speculation` + `npm run build`。手测：长 Bash 中 Ctrl+C 应立即 aborted 不卡死；构造 >150k token 会话看 snip→autoCompact。
**常见故障**：abort 后并行子进程未真 kill（僵尸）；`estimateTokens` 忽略图片低估 token；429 与网络抖动共享重试预算；autoCompact 摘要为空仍替换全历史（丢上下文）。
**影响半径**：**项目心脏，半径最大**。改并发/串行分组、abort、autoCompact 分割都属高风险。
**回归清单**：□ vitest 4 套全绿 □ build □ Ctrl+C 即时生效 □ context_length 触发一次压缩重试而非死循环 □ speculation stats 正常。

### 卡 3 · LLM 适配层
**文件**：`llm-adapter.ts`、`anthropic-adapter.ts`、`cloud-gateway.ts`、`effort.ts`
**改动前必读**：① 两路径 usage 口径相反但都「不重复计 cache」—— 改动须与 `session-stats` 对齐；② 流式必须 `include_usage` + done 延后；③ `DYNAMIC_BOUNDARY` 是缓存切分契约；④ effort 导出名是 `EFFORT_GRADIENT`/`EFFORT_LEVELS`（无 `EFFORT_TIERS`），OpenAI 路径 clamp 到 high。
**验证**：`npx vitest run llm-adapter anthropic-adapter cloud-gateway prompt-cache effort effort-fx` + `npm run build`。手测：真实 provider 跑一轮带工具调用，`/cost` 显示 token>0、连续两轮看 cache_read>0。
**常见故障**：移除 `include_usage` → token 归零；tool_call 分片无 index 互相覆盖；effort 正则漏判新模型；Bedrock 默认模型仍是旧 sonnet。
**影响半径**：改 caller/usage 牵连 autoCompact 触发、session-stats、spinner token；改 provider 解析牵连 cli 启动装配。
**回归清单**：□ 6 套 vitest □ build □ /cost token 与命中率合理 □ 非推理模型不收到 reasoning_effort。

### 卡 4 · 系统提示 + git 上下文
**文件**：`system-prompt.ts`、`git-context.ts`
**改动前必读**：① 7 段顺序（工具描述在**最后**）；② `DYNAMIC_BOUNDARY` 改文案破坏缓存命中；③ 动态段拼装在 `buildSystemPrompt` 与 `rebuildDynamicSections` 各一份，新增字段同步两处；④ git 输出按正斜杠处理，别改 `path.sep`。
**验证**：`npx vitest run system-prompt anthropic-adapter git-context` + `npm run build`。注意 `gatherDiffSummary`/`suggestCommitSubject` **无测试** → 改它们手测 `/commit` `/pr`。
**常见故障**：date 固化进静态段会过期；numstat 路径含空格/重命名匹配错位；无 upstream 时 `/pr` 空输出；CI 缺 git 时测试假绿。
**影响半径**：改静态段影响所有会话模型行为 + 缓存命中；改 diff 摘要牵连 `/commit` `/pr`。
**回归清单**：□ vitest □ build □ DYNAMIC_BOUNDARY 与 adapter 逐字一致 □ `/commit` 主题草稿合理。

### 卡 5 · 工具系统
**文件**：`tool-registry.ts`、`tools.ts`、`tools-m8.ts`、`tools-m8-interactive.ts`、`tools-m9.ts`、`tools-team.ts`、`task-tool.ts`、`todo-tool.ts`、`web-fetch.ts`、`web-search.ts`
**改动前必读**：① Bash 红线（进程树杀 + timedOut 标志 + 非并发安全）；② 写类工具三道关；③ Edit/MultiEdit 用 indexOf 拼接 + 编辑后 refreshRead；④ `task-tool` 依赖 agent-loop/llm-adapter/subagents（**非 system-prompt**），别直 import tools.ts（循环）；⑤ `CORE_TOOLS` 撞名启动即抛；⑥ ToolSearch/MCP 资源是工厂需 cli 注入。
**验证**：`npx vitest run tools tools-m5 tools-m8 tools-m9 team new-tools web-search` + `npm run build`。改 Bash/Grep 必须 Windows 手测（见验证手册）。
**常见故障**：回退 exec 复发死锁；Grep 回退仅扫前 100 文件；NotebookEdit 重写丢 outputs；todo 全量替换误删；web-search 随 DDG 改版失效；task 信号量 slot 泄漏。
**影响半径**：`tools.ts` 极高（CORE_TOOLS 是能力总装配点 + Bash/Edit 影响每次写操作）；`tool-registry.createTool` 是全部工具构造入口。
**回归清单**：□ 多套 vitest □ build □ Bash 超时/Ctrl+C/无孤儿（Windows）□ 写工具越界被拒 □ 新工具不撞名。

### 卡 6 · 权限 / 安全 / 拦截
**文件**：`permissions.ts`、`read-tracker.ts`、`hooks.ts`、`change-tracker.ts`
**改动前必读**：① `checkPermission(tool,input,context,options)` 四参；② 分类器 fail-safe + ALLOW≠放行 + BLOCK 前置；③ 执行管线顺序 `runPre→checkPermissions→checkPermission→call→runPost` 不可乱；④ `checkDangerousPattern`/`isBlockedPath` 被双路径消费；⑤ `change-tracker` 导出是 `listChanges`（非 getChanges）；⑥ `refreshRead` 必调。
**验证**：`npx vitest run permissions read-tracker hooks change-tracker tools tools-m8 mcp-permissions` + `npm run build`。手测：plan 模式拒写、bypass 放行 rm -rf、hook block 工具不执行副作用。
**常见故障**：dev-server 正则误命中 `npm start`；分类器半截输出误判 BLOCK；Windows 盘符大小写越界误判；hook 异常被吞成工具错误。
**影响半径**：改危险正则双路径影响全部破坏性工具；改 `checkPermission` 步骤顺序改变所有工具权限语义；read-tracker 放松影响所有写工具。
**回归清单**：□ vitest 多套 □ build □ 四模式行为正确 □ 分类器失败降级为提示 □ hook pre 在权限前。

### 卡 7 · 子代理与团队
**文件**：`subagents.ts`、`team.ts`
**改动前必读**：① 核心工具由 cli 注入（`setCoreToolsForSubagents`）打破循环，dynamic import 仅回退；② `toolNames` 必须与 `CORE_TOOLS` 名字完全一致（否则静默丢弃）；③ 它是 Task enum 与 Team 角色唯一真源；④ team 受限预算 10turn/50k；⑤ askUser 必须透传（红线）；⑥ stopped 优先于 done。
**验证**：`npx vitest run subagents team tools` + `npm run build`。team.test mock 了 llm-adapter，改 `runAgentTurn` 事件循环/abort 须真实 provider 手测。
**常见故障**：`_coreTools`/`SUBAGENT_TYPES` 模块单例跨测试泄漏（无 reset）；解析不到工具静默缩小工具集；team 缺 `modelConfig` 全报错；background 错误只落 agent 内部。
**影响半径**：改类型/工具集改变子代理与团队成员能力边界与权限面；是两条链路共同上游。
**回归清单**：□ vitest □ build □ code-reviewer 仍只读 □ 子代理破坏性工具仍提示 □ background 轮询 running→done 可见。

### 卡 8 · MCP 集成
**文件**：`mcp.ts`、`mcp-auth.ts`
**改动前必读**：① `checkPermissions` 是 `.map` 内箭头函数捕获 `this`，别重构成普通方法（sticky 失效）；② 工具权限保守写死；③ `withTimeout` 只 race 不取消；④ `mcp-permissions.test.ts` 是手抄镜像，改门控须同步；⑤ token 绝不 log；⑥ OAuth 时序与 mcp.ts catch 分支强耦合。

## 常见改动 cookbook

> 每条给出「必改文件 + 同步点 + 验证」。注意各种「双来源/双渲染栈」的同步陷阱。

### A. 新增一个工具
1. 在合适文件用 `createTool` 实现（核心改 `tools.ts`，扩展改 `tools-m8/m9` 等）；按需覆盖 `isReadOnly`/`isConcurrencySafe`/`requiresApproval`/`checkPermissions`/`isEnabled`（如平台条件启用）。
2. 写类工具：必须走 `resolveInWorkspace` + `isBlockedPath` + `checkDangerousPattern`，编辑后 `refreshRead`。
3. 加入 `tools.ts` 的 `CORE_TOOLS` 数组（确认不与现有/MCP/M8/Team/M14 撞名）。
4. 若要进 `ToolRegistry`/`/tools`，确认 `cli.ts` 注册路径覆盖（两套来源同步）。
5. 若子代理也要用：在 `subagents.ts` 内置类型的 `toolNames` 加上同名（大小写一致）。
6. **验证**：写测试加入对应 `*.test.ts`；`npx vitest run tools new-tools` + `npm run build`。

### B. 新增一条斜杠命令
1. 建 `src/commands/<name>.ts`，默认 + 具名导出一个 `SlashCommand`（`{name, description, run}`），`run(args, ctx)` 通过可选 `ctx` 字段读写会话状态、用 `console.log` 输出。
2. 在 `commands/registry.ts` `import` 并推入 `COMMANDS` 数组（位置即 `/help` 顺序）。
3. 若命令需要新会话状态：在 `commands/types.ts` 的 `CommandContext` 加**可选**字段，再在 `cli.ts` 的 `makeCommandContext()`（及 `tui` 的对应构造）注入。
4. 若是 prompt 注入型：`run` 返回 `{ prompt }`，确认 cli.ts 与 tui/run.tsx 的 prompt 分支都接（两条前端）。
5. **验证**：`npx vitest run commands` + `npm run build`；两条前端各手测一次。

### C. 接入一个新 provider
1. 扩 `llm-adapter.ts` 的 `PROVIDER_CONFIGS` / `resolveProviderConfig`；纯网关型可走 `cloud-gateway.ts`（改 `CloudGateway` 联合 + `DEFAULTS` + `isCloudGateway` + `resolveGateway` 四处）。

5. **验证**：`npx vitest run llm-adapter cloud-gateway` + 真实 provider 跑一轮看 `/cost`。

### D. 新增一个子代理类型
1. `subagents.ts` 用 `registerSubagentType` 注册（或加内置），声明 `toolNames`（**必须与 CORE_TOOLS 名字完全一致**）+ `systemPrompt`。

## 文档与计数同步责任

历史上反复出现「文档数字漂移」（48 文件 vs 实际 97、18 命令 vs 37、24 工具 vs 30）。约定：

- **改动伴随结构变化时同步文档**：新增/删除模块 → 更新《项目架构.md》模块清单 + 索引 + 计数；新增命令/工具 → 更新对应清单与计数。
- **可一键复核的计数命令**（写更新日志或 review 时核对）：
  ```bash
  # 非测试源文件数（应与文档「97」一致）
  find src -type f \( -name '*.ts' -o -name '*.tsx' \) | grep -v __tests__ | wc -l
  # 测试文件数
  find src/__tests__ -type f | wc -l
  # 命令数（应 = COMMANDS.length）
  grep -cE '^\s*\w+Command,' src/commands/registry.ts
  # 工具名去重数
  grep -rhoE 'name: "[a-z_0-9]+"' src/tools*.ts src/task-tool.ts src/todo-tool.ts src/web-*.ts | sort -u | wc -l
  ```
- **每次改动留一条更新日志**（见 [`更新日志/README.md`](./更新日志/README.md)）：记录模块、受影响文件、根因、验证结果、commit —— 这是「出 bug 可追溯」的最后一环。
