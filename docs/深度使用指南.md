## 一、Headless / 自动化模式

`-p` / `--print` 把 CLI 变成脚本可编排的单次执行器（源码：`src/cli-headless.ts`，
e2e 测试：`src/__tests__/cli-headless-e2e.test.ts`）。

```bash
# 最基本：打印回答后退出
node dist/cli.js -p "总结 src/cli.ts 的职责"

# 结构化输出（CI 可解析）：json = 最终汇总帧；stream-json = 逐事件流（NDJSON）
node dist/cli.js -p "..." --output-format json
node dist/cli.js -p "..." --output-format stream-json --verbose

# 防止失控：限制轮数与预算
node dist/cli.js -p "..." --max-turns 10 --max-budget-usd 0.5

# 无交互环境必须收紧权限（否则需要审批的工具调用直接失败，fail-closed）
node dist/cli.js -p "把 a.ts 重命名为 b.ts" \
  --permission-mode acceptEdits \
  --allowedTools "Read,Edit,Glob" --disallowedTools "Bash"

# 继续/恢复会话（跨进程续跑）
node dist/cli.js -p "第一轮指令" --output-format json   # 记下返回帧里的 session_id
node dist/cli.js -p "接着做" --resume <session_id>
node dist/cli.js -p "接着做" --continue                 # 接续最近一次会话

# 从 stdin 喂入（管道编排）
echo "审查这段代码" | node dist/cli.js -p
git diff | node dist/cli.js -p "总结这次改动" --output-format json

# 在隔离 worktree 中执行（不脏当前工作区）
node dist/cli.js -p "重构 utils 模块" --worktree

# 结构化提取：强制输出符合 JSON Schema 的结果
node dist/cli.js -p "提取 TODO 列表" \
  --json-schema '{"type":"object","properties":{"todos":{"type":"array","items":{"type":"string"}}}}'
```

实用要点：

- `--quiet`（默认）只输出回答；`--verbose` 输出工具调用过程。
- headless 下无审批渠道——需要审批的工具调用会被拒绝。要么
  `--permission-mode bypassPermissions`（仅限沙箱！），要么用
  `--allowedTools` 精确放行。
- `--output-format json` 的最终帧含 `session_id` / `usage` / `result`，供脚本解析。
- 退出码非 0 即失败，可直接进 CI 门禁。

## 二、子代理深度使用

子代理通过 Task/Agent 工具由主代理自主调度（源码：`src/tools/extended/agent.ts`、
`src/task.ts`、`src/agents/`）。用户在 REPL 里用自然语言即可触发，也可用
`.claude/agents/*.md` 预定义专用代理。

### 2.1 内建代理类型

| 类型 | 用途 | 工具集 |
|---|---|---|
| （省略）/ `general` | 通用多步任务，继承全部工具 | 全部（`tools: ["*"]`） |
| `code-explorer` | 只读快速定位代码（where is X） | Read/Grep/Glob 等只读 |
| `code-reviewer` | 独立代码审查，结构化 findings | 只读为主 |
| `fork` | **显式**分叉当前代理：继承对话上下文与提示词缓存 | 继承 |

提示词示例：

```
用 Task 工具起一个 code-explorer 找出所有调用 resolveProviderConfig 的地方
起一个 code-reviewer 审查刚才的改动，列出 correctness 类问题
```

### 2.2 关键参数（对齐官方 2.1.202 语义）

- `subagent_type`：省略 = general（官方语义，**不再是 fork**）；`"fork"` 仅显式。
  类型名归一化：大小写/空白/连字符不敏感。
- `model`：单次覆盖子代理模型。优先级：`CLAUDE_CODE_SUBAGENT_MODEL` 环境变量 >
  调用参数 > 磁盘 frontmatter > 主模型。
- `run_in_background: true`：立即返回，子代理异步跑，结果稍后收取。
- 后台作业用 `job_output` 读取，返回状态和实际退出码；取消使用 `job_kill`，终态等进程或代理清理完成后发布。`job_output` 的等待可以取消，不会连带结束后台任务。Bash 后台任务可跨普通回合运行；后台 Agent 的父级取消仍会级联。主会话可管理子代理启动的后台任务，子代理只能访问自身及下级任务，恢复执行后保留该范围。CLI 正常结束会清理本次访问过的会话作业并保存最终诊断；旧会话只更新后台记录，保留目标、队列和保存时间。未完成任务不会在新进程自动重启。见[后台归属记录](更新日志/20261112-background-job-ownership.md)及[生命周期与强制退出边界](更新日志/20261112-background-process-lifecycle.md)。
- `resume: "<agent_id>"`：恢复一次 typed 子代理运行（含其完整对话历史）。
  运行记录落盘 `.claude/sessions/subagents-<session_id>/`，`/agents history`
  可列。崩溃/中断的运行状态自动修复为 `interrupted`，可安全 resume。
- `permissions.deny` 可按子代理类型禁用：settings 里
  `Agent(subagent_type=code-reviewer)` 这样的规则会精确拦截。

### 2.3 磁盘自定义代理：`.claude/agents/<name>.md`

```markdown
---
name: pr-reviewer
description: Review a diff for correctness and security
whenToUse: When you want an independent review of pending changes
tools: [read, grep, glob]
maxTurns: 20
model: sonnet
omitClaudeMd: true
---
You are a careful pull-request reviewer. Read the diff and report …
```

（源码：`src/agents/loadAgentsDir.ts`）扫描根：`~/.claude/agents/`（用户级）→
`<项目>/.claude/agents/`（项目级优先）。frontmatter 支持
`name/description/whenToUse/tools/maxTurns/memory/model/omitClaudeMd/mcpServers`。

**信任边界**：项目级代理文件的 `mcpServers` 块会触发一次性
（agent + 内容指纹）信任确认，提示中显示 command/url/env/header 键名后才允许
spawn（源码：`src/agents/agent-mcp.ts`）。改动文件内容会使旧信任失效。

### 2.4 强制统一子代理模型（省钱/控速）

```bash
# .env
CLAUDE_CODE_SUBAGENT_MODEL=deepseek-chat   # 所有子代理强制用此模型
```

## 三、Hooks 编排

在 `.claude/settings.json` 声明 shell 钩子，在代理循环的关键事件点注入外部逻辑
（源码：`src/hooks.ts` + `src/hooks-config.ts`，官方协议兼容）。

### 3.1 支持的事件

| 事件 | 时机 | 可做的事 |
|---|---|---|
| `PreToolUse` | 工具调用前（权限检查之前） | 放行/询问/阻断、改写输入、附加上下文 |
| `PostToolUse` | 工具执行后 | 替换返回给模型的结果 |
| `Stop` | 一轮即将自然结束时 | `block` 让代理继续干活（带防死循环闸门） |
| `UserPromptSubmit` | 用户提交输入后 | 附加/改写提示 |
| `SessionStart` / `SessionEnd` | 会话启停 | 初始化/清理 |
| `Notification` | 通知触发时 | 转发到外部（如桌面通知） |
| `SubagentStop` | 子代理结束时 | 审计 |
| `PreCompact` | 上下文压缩前 | 存档 |

### 3.2 配置格式与协议

```json
{
  "hooks": {
    "PreToolUse": [
      {
        "matcher": "Edit|Write",
        "hooks": [{ "type": "command", "command": "node scripts/lint-gate.mjs", "timeout": 60 }]
      }
    ],
    "Stop": [
      {
        "matcher": "",
        "hooks": [{ "type": "command", "command": "node scripts/check-done.mjs" }]
      }
    ]
  }
}
```

- `matcher` 匹配工具名（正则，`"*"`/空 = 全部）；`Stop` 等事件不匹配工具名。
- stdin 收到官方信封 JSON：`session_id`、`transcript_path`、`cwd`、
  `hook_event_name` + 事件字段（`tool_name`/`tool_input`/`tool_response`/
  `stop_hook_active` 等）。
- 决策出口（优先级从高到低）：
  1. **exit code 2**：stderr 文本即阻断理由，反馈给模型（`echo reason >&2; exit 2`）。
  2. stdout JSON：`{ "decision": "block", "reason": "…" }`。
  3. 其他：放行。
- 钩子在工作区根执行，`CLAUDE_PROJECT_DIR` 指向工作区。
- **失败安全**：钩子报错/超时/输出非法 JSON = 放行，永不阻塞工作。

### 3.3 信任门（安全关键）

项目 settings 里的 hooks 可执行任意命令，所以：

- 首次见到（或内容变更后）会要求显式信任确认，指纹缓存于用户级记录；
- 未信任的 hooks 块会被拒绝加载并提示；
- `settings.local.json`（个人覆盖）同样走信任门。

### 3.4 实战配方

**提交前 lint 门**：PreToolUse 匹配 `Bash`，命令里 grep `git commit` 时先跑 lint，
失败则 exit 2 把错误喂回模型让它修。

**自动测试回路**：Stop 钩子跑 `npm test`，失败时 `decision:block` + 原因——
代理会继续修到测试全绿才停（有 `stop_hook_active` 防死循环）。

**编辑后格式化**：PostToolUse 匹配 `Edit|Write`，对 `tool_input.file_path`
执行 prettier，把格式化结果写回 `tool_response`。

## 四、MCP 深度配置

`.claude/mcp.json`（源码：`src/mcp/index.ts`）：

```json
{
  "mcpServers": {
    "fs-extra": {
      "type": "stdio",
      "command": "npx",
      "args": ["-y", "@modelcontextprotocol/server-filesystem", "."],
      "env": { "API_TOKEN": "${MY_MCP_TOKEN}" }
    },
    "remote-search": {
      "type": "http",
      "url": "https://mcp.example.com/search",
      "headers": { "Authorization": "Bearer ${REMOTE_MCP_KEY}" }
    }
  }
}
```

要点：

- `type` 可省略：`command` → stdio，`url` → http。支持 stdio/http/sse/ws。
- `${ENV_VAR}` 语法从 `process.env` 展开（key 放环境变量，不落盘）。
- **信任门**：项目级 mcp.json 可 spawn 任意命令，首次见到会显示
  command/url/env/header 键名请求一次性信任（按路径+内容指纹）；改动即失效重问。
- 工具命名空间冲突（两个服务器提供同名工具）会一次性 `console.warn` 提示。
- http/sse 传输支持 OAuth 2.0（`oauth` 块）——服务器侧能力，本地无需账号。
- stdio 子进程只继承白名单环境变量（`PATH`/`HOME` 等），防泄漏。

## 五、SDK 编程式使用

### 5.1 TypeScript（`dist/sdk.js`，源码 `src/sdk.ts`）

```ts
import { query } from "claude-code-replica/sdk"; // 或相对路径 ../dist/sdk.js

for await (const msg of query({
  prompt: "统计 src 下的 TODO 数量",
  options: {
    model: "deepseek-chat",
    maxTurns: 5,
    maxBudgetUsd: 0.2,
    allowedTools: ["Grep", "Glob", "Read"],
    resume: "session-id-从上次-result-帧拿到",  // 可选
    cwd: "/path/to/project",
  },
})) {
  if (msg.type === "result") console.log(msg.result, msg.session_id);
}
```

- `prompt` 也接受 `AsyncIterable<string>`（流式多轮喂入）。
- CLI 退出、外部取消或 `await q.return()` / `await q.throw(error)` 会停止拉取输入，迟到输入不再写回。关闭操作能打断等待消息的 `q.next()`；SDK 会请求输入迭代器的 `return()`，但不会无限等待不合作的输入源。输入生成器内部的任意 await 无法被 JavaScript 强制取消，长等待应由调用者通过自己的 AbortSignal 或队列关闭机制解除。
- `options.signal`（AbortSignal）可随时中止。
- 本质是 spawn 一个 `--print --input-format stream-json --output-format stream-json`
  子进程并解析 NDJSON；stdout 混入非 JSON 行会被降级为
  `type:"system", subtype:"non_json_stdout"` 消息而不是炸掉生成器。
- 需要已构建的 `dist/`（或显式传 `cliModule`/`cliExecutable`）。
- 回合结果到达会取消仍挂起的 `canUseTool` 回调 signal；回调应响应取消，迟到的决策不再回写。关闭 query 时若所有已发送回合都有结果，先给 CLI 1 秒正常 EOF 清理时间；还有未完成回合时发送本项目 `shutdown` 控制帧，取消当前回合并丢弃排队输入。250 毫秒内未结束则终止自有 CLI 进程树并等待退出。外部取消和输入源异常也走同一收尾；消费者暂停时取消仍能执行。
- CLI 正常退出但尚有已提交请求缺少结果帧时，查询报错；输入源失败也会作为查询错误返回，不能把流结束当成任务完成。多轮中断与恢复验收见[连续性记录](更新日志/20261111-ts-sdk-continuity.md)。
- 本项目 CLI 和两端 SDK 用 `input_id` 将结果对应到已提交的输入。恢复后的新输入会获得新标识，`session_id` 仍用于恢复会话。重复、乱序或缺少必需标识的结果会产生 `invalid_protocol_message` 诊断。旧 CLI 按提交顺序消费结果，有结果 UUID 时可以识别重复帧。见[结果归属记录](更新日志/20261112-sdk-result-ownership.md)。
- `updatedInput` 可经过子代理审批通道，按实际执行者的工作区与权限规则复核。输出中的非法消息信封会转为 `system / invalid_protocol_message` 诊断；TS RPC 的非法控制回复会拒绝对应方法调用。详见[契约修复记录](更新日志/20261111-sdk-approval-contract.md)。

源码 checkout 可运行 `npm run eval -- examples/core-eval-suite.json --repeat=2`，测量隔离的读码、单文件修复与跨文件修复任务；准备、限制与报告格式见[核心编码任务测量](core-evaluation.md)。

权限回调与运行中控制（官方 Agent SDK 形状的控制协议）：

```ts
const q = query({
  prompt: "整理这个仓库",
  options: {
    canUseTool: async (toolName, input, ctx) => {
      // 默认模式下需要审批的工具调用会走到这里（CLI 侧走
      // --permission-prompt-tool stdio 的 can_use_tool 控制帧）。
      if (toolName === "bash") return { behavior: "deny", message: "CI 不跑 shell" };
      return { behavior: "allow" }; // 可附 updatedInput 改写审批询问的参数
    },
  },
});
for await (const msg of q) {
  if (msg.type === "assistant") await q.interrupt(); // 运行中也可调用
}
// 另有 q.setPermissionMode("acceptEdits") / q.setModel("...")；
// 控制帧不会作为消息 yield 出来。回调抛错 = 拒绝（fail-closed）。
```

- 不设 `canUseTool` 时 headless 审批依旧自动拒绝，行为与旧版一致。
- `updatedInput` 适用于中央权限询问（标准审批与危险模式安全底线，两条路径都会对改写后的输入重跑完整权限复查再执行）；工具内部审批（如 MCP/MemorySave 内部调用 `askUser`）若返回改写参数按拒绝处理，避免原参数未经复查继续执行。
- stdin 在输入耗尽且每个 prompt 都收到 result 帧后才关闭；控制方法带 60s 超时。
- 审批等待没有超时，但 stdin EOF / 会话结束会把挂起审批全部拒绝，不会挂死。

### 5.2 Python（`python/ccr_sdk.py`，Python 3.10+）

```python
import asyncio
from ccr_sdk import query

async def main():
    async for msg in query("总结 README", cwd=r"D:\path\to\project",
                           model="deepseek-chat", max_turns=5):
        if msg.get("type") == "result":
            print(msg["result"])

asyncio.run(main())
```

`query(prompt, *, cwd, env, model, max_turns=8, resume=None, can_use_tool=None, cli=None)`
——同样是子进程封装，key 走环境变量（`LLM_API_KEY` 等）。

```python
async def approve(tool_name, tool_input, context):
    # context["suggestions"] 目前恒为空列表；返回 allow/deny 决定
    return {"behavior": "allow"}

async for msg in query("整理仓库", can_use_tool=approve):
    ...
```

- `can_use_tool` 启用与 TS 相同的 stdio 控制协议；回调抛错按拒绝处理。
- `cli` 可显式指定 CLI 入口（默认 `dist/cli.js`），测试可传 fixture。
- 一次性 `query()` 消费到流结束时，也会返回结果帧之后的异常退出诊断。

持续会话使用本项目的 `CCRClient`，保持同一个 CLI 进程与对话历史：

```python
from ccr_sdk import CCRClient

async def coding_session():
    async with CCRClient(cwd="/path/to/project", model="deepseek-chat",
                         can_use_tool=approve) as client:
        await client.query("运行测试，定位失败原因")
        async for msg in client.receive_response():
            if msg["type"] == "result":
                session_id = msg["session_id"]
                print(msg.get("result"), msg.get("is_error"))

        await client.set_model("another-provider-model")
        await client.set_permission_mode("default")
        await client.query("修复刚才的问题，再次运行测试")
        async for msg in client.receive_response():
            print(msg)

    # 新进程可用 CCRClient(resume=session_id, ...) 恢复磁盘会话。
```

- `connect()` / `disconnect()` 可替代 `async with`；关闭会取消挂起审批、拒绝挂起 RPC 并等待 CLI 退出。已关闭的客户端不能重新连接，应创建新实例。
- `disconnect()` 遇到未完成回合先发送本项目 `shutdown` 控制帧取消当前回合、丢弃排队输入；250 毫秒未退出时终止自有 CLI 进程树。全部回合已有结果时先允许正常 EOF 清理。`async with` 中任务被取消也会清理；希望保留正常中断结果时，先 `interrupt()` 并消费结果，再断开。
- 上述树清理在 Windows 普通自有进程上已有验收；已脱离或失去父关系的后代不能据此保证。硬停止不保证最终保存，恢复使用最后快照并标记后台中断，见[SDK 进程树记录](更新日志/20261112-sdk-process-tree.md)。
- `interrupt()` 中断当前回合，结果帧仍可读取，后续回合可以继续。回合结果到达时取消该回合的审批 task；即使回调吞掉取消异常，也不会写回迟到的决策。
- `receive_response()` 读取到一个结果帧；`receive_messages()` 读取到进程退出。应完整消费或显式关闭迭代器，同一客户端只允许一个消息消费者。后台读取任务独立处理控制回复，消费者暂停时调用控制方法也不会死锁。
- `finish()` 表示不再发送用户消息；等所有已发送回合都有结果后才关闭 stdin。需要排队多个回合并等 CLI 正常退出时，可调用 `finish()` 后消费 `receive_messages()`。
- 控制请求默认超时 60 秒，可用 `control_timeout` 调整；超时或非法回复会拒绝对应调用。`set_model` 要求显式模型名，模型路由继续遵循现有 provider 配置。
- 协议级测试：`python -m unittest discover -s python -p 'test_ccr*.py'`（Node fixture，无需 provider）。真实 CLI 的中断、继续、文件重写和新进程恢复由 `sdk-python.test.ts` 验收，详见[实现记录](更新日志/20261111-python-persistent-client.md)。

## 六、权限与 Plan 模式进阶

基础四模式见[快速开始.md](快速开始.md)第二节。进阶：

### 6.1 settings.json 细粒度规则

```json
{
  "permissions": {
    "allow": ["Bash(npm test*)", "Read", "Grep"],
    "ask":   ["Bash(git push*)"],
    "deny":  ["Bash(rm -rf*)", "Agent(subagent_type=code-reviewer)"]
  }
}
```

- 复合命令按 `&&`/`||`/`;`/`|` 切段判定：任一段命中 deny/ask 即触发，allow 需每段都命中。
- `deny` 的 `Agent(subagent_type=…)` 可按子代理类型精确禁用。

### 6.2 Plan 模式工作流

```bash
node dist/cli.js --permission-mode plan
```

- 全写操作被阻断，代理只能只读分析并产出计划；确认后 `/mode default` 切换执行。
- 适合：大改造前的方案评审、陌生仓库的初步摸底。

### 6.3 其他开关

| 开关 | 作用 | 警告 |
|---|---|---|
| `--dangerously-skip-permissions` | 跳过全部权限检查 | 仅限一次性沙箱容器 |
| `--read-only` | 强制只读 | 比 plan 更硬的演示模式 |
| `--safe-mode` / `--bare` | 禁用 hooks/skills/插件/自定义命令 | 排障基线 |
| `--llm-perm-classifier` | 用 LLM 给权限请求分类风险 | 额外 token 开销 |
| `/permissions` | 会话内查看/清空 always-allow 记忆 | — |

## 七、会话管理与记忆

- 会话落盘 `<项目>/.claude/sessions/`；`/sessions` 列表、`/resume <id>` 或
  CLI `--resume/--continue` 恢复。
- `/compact` 手动压缩；自动压缩在上下文接近上限时触发（`PreCompact` 钩子可介入）。
- `/diff` 查看本会话所有文件改动；`/cost` 看 token 与估算花费；
  `--max-budget-usd` 给 headless 加硬顶。
- **CLAUDE.md 即长期记忆**：项目根 `CLAUDE.md` 自动注入系统提示；
  `/memory add <text>` 追加；`/init` 生成脚手架。
- 持久记忆工具（MemorySave/recall）：分 user/project/local 三个 scope，
  **全部 scope 写入都需要显式审批**（记忆原文会进后续会话的系统提示，属信任边界）。
- `--worktree` 在临时 git worktree 中工作，完工后可保留或丢弃。
