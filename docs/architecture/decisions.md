# 当前设计决策

> 更新：2026-11-11。此页固定重要决策的导航位置，历史论证见 [9 月架构总纲](../archive/reports/20260925-架构分析与升级总纲.md)。

## 产品方向：从 Claude Code 分叉（2026-11-11 确立）

本项目目标是**从 Claude Code 这个软件分叉(fork)**，不是永远追随官方兼容的复刻；最终产品**不合并回官方**。两条轴：

- **轴 A · 核心引擎继承（分叉前提，必须保真）**：agent 循环、工具系统与行为、权限/安全模型、上下文压缩、流式 + thinking、子代理、模型调用、会话持久化等核心编码能力。分叉前优先保证这条轴的**完整性与行为保真**（同任务下的行为扎实、无浅实现），而不是格式兼容。
- **轴 B · 生态/配置独立（刻意不共用）**：指令记忆、配置层级、扩展格式（Skills / agents / plugins / MCP）、账号 / 云 / IDE 集成。这些是官方的"共用地盘"，分叉产品要有**自己独立、自洽的机制**，不为兼容官方而打通。已有独立基础：用户配置根 `~/.claude-code-replica/`、自有 plugin/skills/agents 格式、自有 MCP 配置、不读官方登录令牌。

**审查与差距分析口径（重要）**：不要把"无法直接复用官方资产""不读官方用户级/祖先/子目录 CLAUDE.md、`.mcp.json`""扩展格式与官方不同""不消费官方 hooks 协议"当成差距或缺陷——在分叉战略下这些是**有意的独立**，是目标而非欠债。真正的差距只在 ① 轴 A 核心继承的完整性/行为保真 ② 轴 B 自有生态的自洽完整。第三方模型支持是分叉的差异化优势。据此，[差距评估](../20261002-claude-code差距评估.md) 中"让官方资产可迁移"一类推荐已被本决策取代。

## 已记录并继续采用的取舍

- 磁盘命令、skill 与插件 MCP 采用安装即信任；模板 shell gate 保留作可选收窄机制。依据：9 月总纲 Top10 #1 / #2 处置标注。
- 原生沙箱为 best-effort 降权，降级时显示告警，不承诺文件系统 jail。依据：Top10 #7 处置标注。
- Shell 修改不进入 checkpoint；文件回退覆盖工具可追踪的修改。
- 全面配置中心化、统一 IR、追加式会话存储、Agent / Task 合并和大对象拆分曾被暂缓。修复具体不变量不要求启动这些工程。

## 本轮修复明确的归属

- 会话持久位置在创建或恢复时绑定；工具工作区可切换。采用稳定位置，避免移动正在使用的索引、blobs 和转录。
- 权限规则属于执行限制，委派仍保留；审批和 overlay 属于能力，必须由调用者选择受限通道。
- loop 内各消费者使用同一个有效 HookRunner，避免上下文有 hook 而执行器没有 hook。
- durable 任务属于创建工作区；session-only 任务同时属于创建会话。非当前归属的任务暂停交付，恢复其会话 / 工作区后可继续。
- 到期但尚未交付的输入保留身份；取消覆盖等待和排队状态。
- 工具注册表是当前工具目录的来源；执行数组与展示列表是它的视图。

这些规则的实现与回归入口见 [当前架构](../项目架构.md) 和 [维护方案](../模块维护方案.md)。
